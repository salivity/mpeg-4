How MP4 Handles Non-Contiguous Edit Lists via elst

This article provides an overview of how MPEG-4 (ISO Base Media File Format) containers utilize the Edit List box (elst) to orchestrate non-contiguous playback timelines. By manipulating the mapping between stored media samples and presentation time, the elst box enables features such as non-linear segment splicing, timeline gaps, and non-destructive trimming without requiring the underlying audio or video payloads to be re-encoded or physically rearranged.

The Edit List box resides inside the Edit box (edts), which is contained within an individual Track box (trak). The elst table defines an ordered array of edit segments. Each entry in this table specifies three primary fields: segment_duration (the duration of the edit in the movie timeline timescale), media_time (the starting position within the track's raw media timeline), and media_rate (the playback speed, where 1.0 represents standard playback).

To handle non-contiguous media—such as jumping past an unwanted section of video or assembling separate clips into a single continuous presentation—the container defines multiple consecutive entries in the elst box. For example, if a track contains continuous media from timestamp 0 to 60 seconds, but the presentation must skip the section between 15 and 45 seconds, the elst box will contain two distinct entries:

  1. An initial entry with a media_time of 0 and a segment_duration corresponding to 15 seconds.
  2. A subsequent entry with a media_time of 45 seconds and a segment_duration corresponding to 15 seconds.

When a media player parses these entries, it plays the first 15 seconds of raw data, immediately seeks to the 45-second mark in the media stream, and plays the remaining 15 seconds. The player treats these separate media segments as a single, contiguous 30-second presentation timeline, bypassing the intermediate data completely.

Non-contiguous edits can also represent gaps or delays on the presentation timeline where no underlying media should play. This is achieved using an "empty edit." An empty edit is signaled by setting the media_time field to -1 (represented as 0xFFFFFFFF in 32-bit versions or 0xFFFFFFFFFFFFFFFF in 64-bit versions). When the demuxer encounters an empty edit, it advances the presentation timeline by the specified segment_duration while outputting silence for audio or holding/blanking the frame for video until the next valid edit segment begins.

Through this mechanism, the elst box decouples the composition timestamps (CTS) and decoding timestamps (DTS) of the stored samples from the final presentation timeline. Demuxers and decoders use this mapping to determine sample presentation boundaries, handle composition offsets caused by frame reordering (such as B-frames), and execute timeline cuts seamlessly.

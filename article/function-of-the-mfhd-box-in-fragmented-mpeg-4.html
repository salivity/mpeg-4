Function of the MFHD Box in Fragmented MPEG-4

This article provides an overview of the Movie Fragment Header box (mfhd) within the ISO Base Media File Format (ISOBMFF) and fragmented MPEG-4 (fMP4) streams. It explains the structural role of the mfhd box, its core function of storing sequential fragment counters, and why it is critical for maintaining stream continuity, error detection, and synchronization in modern adaptive streaming protocols like MPEG-DASH and HLS.

What Is the mfhd Box?

In fragmented MPEG-4 files, media is divided into smaller, self-contained segments rather than being stored in a single large media data block. Each fragment consists of a Movie Fragment box (moof) containing metadata, immediately followed by a Media Data box (mdat) containing the raw audio or video samples.

The Movie Fragment Header box (mfhd) is a mandatory box located directly inside the moof box. Defined by the ISO/IEC 14496-12 standard, its primary purpose is to carry specific control metadata for the parent fragment.

Primary Function: The Sequence Number

The core payload of the mfhd box is a 32-bit integer called the sequence_number.

When a media stream is fragmented, each successive moof box is assigned an incrementally increasing sequence number starting from 1. The mfhd box stores this number to serve several key operational functions:

  • Fragment Ordering: In network environments where delivery is non-guaranteed or multi-threaded, media fragments might arrive out of order. Media players read the sequence_number in the mfhd box to reassemble fragments in their intended chronological order.
  • Loss Detection: If a sequence jump occurs (for example, receiving fragment 14 directly after fragment 12), the media demuxer immediately knows that fragment 13 was dropped, allowing it to request a retransmission or handle the gap gracefully without corrupting playback.
  • Duplicate Detection: In adaptive streaming, redundant requests or alternate CDN paths can result in duplicate segments arriving at the client. The sequence number allows the player to identify and discard redundant fragments.

Structure of the mfhd Box

The mfhd box is a FullBox, meaning it extends the basic box structure with version and flag fields:

  • Size (32 bits): Total size of the mfhd box.
  • Type (32 bits): The four-character code 'mfhd' (0x6D666864).
  • Version (8 bits): Set to 0.
  • Flags (24 bits): Reserved for future extensions, typically set to 0.
  • Sequence Number (32 bits): The sequential index of the movie fragment.

Role in Adaptive Streaming Protocols

In traditional MP4 files, all structural and timing metadata is located in a single initial moov (Movie) box. This design is unsuitable for live streaming or low-latency playback because the entire file metadata must be generated beforehand.

Fragmented MP4 solves this by using an initialization segment containing a minimal moov box, followed by a continuous series of moof and mdat pairs. In protocols such as MPEG-DASH, CMAF (Common Media Application Format), and fragmented HLS, the mfhd box provides the necessary timeline continuity to bind these independent chunks into a seamless, uninterrupted media stream.

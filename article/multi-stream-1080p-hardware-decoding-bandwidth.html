Multi-Stream 1080p Hardware Decoding Bandwidth

This article provides an overview of the memory bandwidth requirements for multi-stream 1080p MPEG-4 hardware decoding. It breaks down the mathematical calculation for a single 1080p stream at standard color formats, analyzes memory access patterns including reference frame reads and reconstructed frame writes, and provides total throughput estimates for scaling across multiple concurrent streams in embedded and server architectures.

Per-Stream Bandwidth Fundamentals

Hardware video decoding requires continuous data transfers across the system memory bus. A standard 1080p video stream has a resolution of \(1920 \times 1080\) pixels. Most MPEG-4 video (including MPEG-4 Part 2 and MPEG-4 Part 10 / H.264) is decoded into the standard YUV 4:2:0 chroma subsampling format.

In YUV 4:2:0:

  • The luma (Y) plane uses 1 byte per pixel: \(1920 \times 1080 = 2,073,600\text{ bytes}\)
  • The chroma (U and V) planes use 0.5 bytes per pixel combined: \(1,036,800\text{ bytes}\)
  • Total size per uncompressed frame: \(\approx 3.11\text{ MB}\) (\(24.88\text{ Mbits}\))

At 30 frames per second (fps), the uncompressed pixel throughput is: \[\text{Pixel Rate} = 3.11\text{ MB} \times 30\text{ fps} \approx 93.3\text{ MB/s}\]

At 60 frames per second (fps), the uncompressed pixel throughput is: \[\text{Pixel Rate} = 3.11\text{ MB} \times 60\text{ fps} \approx 186.6\text{ MB/s}\]

Memory Access Operations in Hardware Decoders

Hardware decoders perform multiple memory read and write transactions per frame:

  1. Compressed Bitstream Read: The decoder fetches the compressed stream from system RAM. At typical 1080p bitrates (5 to 20 Mbps), this requires only 0.6 MB/s to 2.5 MB/s, which is negligible compared to pixel traffic.
  2. Reconstructed Frame Write: The decoder writes the newly reconstructed frame back into RAM (the Decoded Picture Buffer, or DPB). This requires \(1.0\times\) the uncompressed frame rate (\(\sim 93.3\text{ MB/s}\) at 30 fps).
  3. Reference Frame Read (Motion Compensation): To decode P-frames and B-frames, the hardware must read reference frames from RAM. Due to sub-pixel interpolation, motion vector fetches, and block boundary overlaps, this step typically requires \(1.5\times\) to \(2.5\times\) the uncompressed frame rate, depending on decoder cache size and internal tiling efficiency (\(\sim 140\text{ MB/s to } 233\text{ MB/s}\) at 30 fps).
  4. Display Output Read: If the decoded stream is simultaneously read by a display controller or video compositor, it requires an additional \(1.0\times\) uncompressed frame rate (\(\sim 93.3\text{ MB/s}\) at 30 fps).

Baseline Total Per Stream (30 fps)

  • Core Decode Only (No Display): \(235\text{ MB/s to } 330\text{ MB/s}\)
  • Core Decode + Display Output: \(330\text{ MB/s to } 425\text{ MB/s}\)

Multi-Stream Bandwidth Scaling

When processing multiple streams concurrently, total memory bandwidth scales almost linearly. However, multi-stream workloads reduce internal cache hit rates and cause memory controller page-open/page-close thrashing, introducing a 10% to 20% arbitration efficiency penalty.

The table below outlines real-world bandwidth requirements (assuming 30 fps, YUV 4:2:0, moderate cache efficiency, and decode-only operation):

Concurrent 1080p Streams Raw Decode Bandwidth Estimated Total with Overhead (15%)
1 Stream \(\sim 280\text{ MB/s}\) \(\sim 322\text{ MB/s}\)
4 Streams \(\sim 1.12\text{ GB/s}\) \(\sim 1.29\text{ GB/s}\)
8 Streams \(\sim 2.24\text{ GB/s}\) \(\sim 2.58\text{ GB/s}\)
16 Streams \(\sim 4.48\text{ GB/s}\) \(\sim 5.15\text{ GB/s}\)

(Note: For 60 fps streams, double the throughput requirements).

Hardware Architecture Requirements

To support multi-stream decoding reliably:

  • Memory Bus Utilization: Video decoding memory traffic consists of large bursts of 2D memory access patterns. Memory buses should not be operated above 70–80% of their theoretical peak bandwidth to avoid latency spikes and frame drops.
  • DDR Generation Sizing: A dual-channel LPDDR4-3200 bus provides a theoretical maximum of approximately \(25.6\text{ GB/s}\) (effective \(\sim 18\text{ to } 20\text{ GB/s}\)), which can comfortably handle up to 32 to 40 concurrent 1080p30 decode streams alongside standard OS tasks. A single-channel DDR3-1600 interface (\(\sim 12.8\text{ GB/s}\) theoretical) is limited to roughly 8 to 12 concurrent streams.

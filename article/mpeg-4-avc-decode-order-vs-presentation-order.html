MPEG-4 AVC Decode Order vs Presentation Order

MPEG-4 Advanced Video Coding (AVC / H.264) resolves the discrepancy between decoding order and presentation order primarily through the use of Picture Order Count (POC), the Decoded Picture Buffer (DPB), and transport-level timestamps like DTS and PTS. Because modern video compression relies on bidirectional predictive frames (B-frames) that require future reference frames to be decoded first, the sequence in which the decoder processes frames rarely matches the sequence in which they must be displayed. AVC introduces a robust architectural framework at both the bitstream and buffer levels to ensure frames are presented accurately and smoothly.

Why Decoding and Presentation Orders Differ

In standard video compression, frames are categorized into I-frames (intra-coded), P-frames (predicted from previous frames), and B-frames (bi-directionally predicted from both past and future frames).

To decode a B-frame, the decoder must already have access to the future reference frame it references. Consequently, the encoder must transmit and decode the future reference frame before the B-frame, even though the B-frame must appear on the screen first. This creates a fundamental divergence between the decode order (the bitstream sequence) and the presentation or display order (the visual timeline).

Picture Order Count (POC)

At the video coding layer, AVC introduces the Picture Order Count (POC) to dictate the exact presentation order of decoded pictures.

  • Syntax Placement: POC values are derived from information transmitted in the slice headers of each picture.
  • Function: Unlike traditional frame numbering, which counts frames in the order they are decoded, POC explicitly defines the temporal sequence for display.
  • Motion Compensation: POC is not only used for display sorting; it also enables temporal direct motion vector calculation in B-slices, ensuring motion prediction scales accurately according to the true temporal distance between frames.
  • Modes: AVC supports three different POC derivation modes (Types 0, 1, and 2) to balance bitstream overhead and flexibility depending on the picture structure (fixed frame rates, variable frame rates, or field/frame coding).

The Decoded Picture Buffer (DPB)

The Decoded Picture Buffer (DPB) is the hardware or software memory structure responsible for holding decoded pictures before they are displayed or used as references.

  1. Storage: When a frame is decoded according to its decoding order, it is placed into the DPB.
  2. Reordering: The DPB reorders the stored frames based on their POC values rather than the order in which they arrived.
  3. Output and Removal: AVC utilizes the Hypothetical Reference Decoder (HRD) and Memory Management Control Operations (MMCO) to regulate when a frame is output from the DPB for display and when it can be safely removed from memory to free up space.

Decode Order Identification (frame_num)

While POC handles presentation order, the bitstream tracks decoding order using the frame_num syntax element in the slice header. Each reference frame increments the frame_num, allowing the decoder to detect lost frames in transmission and maintain reference picture lists properly. Non-reference frames do not increment frame_num, keeping the decode-order tracking lightweight.

Container-Level Synchronization (DTS and PTS)

When AVC bitstreams are packaged into container formats (such as MP4, MKV, or MPEG Transport Streams), the system layer complements POC using presentation and decoding timestamps:

  • Decode Time Stamp (DTS): Instructs the decoder exactly when to pull the compressed frame from the buffer and decode it.
  • Presentation Time Stamp (PTS): Instructs the display unit exactly when to render the uncompressed frame to the screen.

Together, the container-level timestamps and the internal AVC syntax (POC and DPB management) guarantee that video frames are decoded in the necessary reference sequence and rendered chronologically without visual stutter or temporal distortion.

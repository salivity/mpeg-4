How MPEG-4 Binary Shape Masking Isolates Objects

This article explains how the MPEG-4 video standard employs binary shape masking to separate foreground visual elements from background content. By utilizing Video Object Planes, binary alpha planes, and specialized macroblock coding, MPEG-4 enables content-based representation, compression, and manipulation of individual visual objects within a dynamic scene.

Video Object Planes and Scene Decomposition

MPEG-4 Part 2 diverges from traditional frame-based video coding by treating scenes as collections of independent entities known as Video Objects (VOs). Each temporal instance of a Video Object is encapsulated within a tight rectangular bounding box known as a Video Object Plane (VOP).

To isolate the visual object from the remainder of the bounding box, MPEG-4 pairs standard texture and motion data with shape information. This shape representation dictates which pixels within the rectangular VOP belong to the semantic foreground object and which represent empty space.

The Binary Alpha Plane

Binary shape coding relies on a Binary Alpha Plane (BAP), a single-bit bitmap synchronized with the luminance component of the video. In this binary mask:

  • Opaque Pixels (Value = 255 or 1): Designate areas that belong entirely to the foreground visual object.
  • Transparent Pixels (Value = 0): Designate areas that lie outside the object boundaries, effectively representing empty space or the background.

By applying this binary grid over the bounding box, the decoder can determine the exact silhouette of the visual object at any given frame.

Macroblock-Based Shape Classification

For transmission and compression efficiency, MPEG-4 divides the binary alpha plane into 16x16 pixel blocks called Binary Alpha Blocks (BABs). Each BAB is classified into one of three operational categories:

  1. All-Transparent: The block contains zero foreground pixels. The encoder completely skips texture and motion encoding for this block, saving significant bitrate.
  2. All-Opaque: The block is entirely filled by the visual object. It is compressed using standard Discrete Cosine Transform (DCT) and motion estimation techniques, requiring no shape transmission overhead.
  3. Boundary: The block contains both opaque and transparent pixels, marking the edge of the visual object. These blocks require explicit binary shape coding alongside adapted texture encoding.

Context-Based Arithmetic Encoding (CAE)

To compress the precise contour within boundary blocks without consuming excessive bandwidth, MPEG-4 uses Context-based Arithmetic Encoding (CAE). CAE leverages statistical dependencies between neighboring shape pixels to predict mask values.

  • Intra-CAE: Uses a 10-pixel spatial template composed of previously decoded adjacent pixels within the current frame to predict the current pixel's binary state.
  • Inter-CAE: Uses a 9-pixel spatio-temporal template combined with shape-specific motion vectors to predict the current boundary based on the object’s contour in preceding frames.

Texture Padding and Final Compositing

Encoding boundary blocks presents a challenge: performing DCT across sharp artificial edges between the object and transparent regions can introduce high-frequency compression artifacts. To resolve this, MPEG-4 applies repetitive padding or low-pass extrapolation. Transparent pixels immediately adjacent to the object boundary are filled with values replicated from nearby opaque pixels before the DCT is calculated.

At playback, the decoder applies the reconstructed binary shape mask to discard the padded values, isolating the crisp foreground contour and allowing it to be composited seamlessly over any target background.

How MPEG-4 Handles Timed Metadata and GPS Data

This article explores how the MPEG-4 container format manages timed metadata, specifically dynamic spatial data such as GPS coordinates. It details the underlying track architecture within the ISO Base Media File Format (ISOBMFF), the synchronization mechanisms that align sensor readings with visual frames, and the process used by decoders to extract and present this continuous stream of positional data alongside audio and video.

The ISO Base Media File Format Architecture

MPEG-4 (MP4) relies on the ISO Base Media File Format (ISOBMFF), which organizes multimedia files into an object-oriented hierarchy of structures called "boxes" or "atoms." Rather than interleaving GPS or sensor data directly into video frames, the specification treats metadata as an independent track (trak box) running parallel to audio and video tracks.

Within a metadata track, the following key structures define the data:

  • Handler Reference Box (hdlr): Defines the track type as metadata by setting the handler type to meta or timed metadata.
  • Sample Description Box (stsd): Specifies the format and schema of the metadata payloads (e.g., standard XML, text, or vendor-specific timed formats like GoPro's gpmd).
  • Media Data Box (mdat): Holds the raw binary payloads containing the actual GPS readings (latitude, longitude, altitude, speed, and heading).

Synchronization via Time-to-Sample Tables

To align GPS coordinates with specific video frames, MPEG-4 uses sample tables located inside the stbl box of the metadata track. These tables map the temporal location of each metadata packet:

  • Time-to-Sample Box (stts): Defines the duration of each metadata sample, assigning continuous time deltas to each entry.
  • Sample Size Box (stsz): Tracks the byte length of each individual GPS sample payload.
  • Chunk Offset Box (stco or co64): Maps the exact byte offsets within the mdat box where each sample resides.

Because both the video track and the metadata track share a common media timeline derived from the movie header (mvhd), each GPS fix is assigned an exact Presentation Time Stamp (PTS). This allows the container to handle mismatched sampling rates effortlessly, such as pairing a 10 Hz GPS receiver with a 60 fps video stream.

Data Formats and Multiplexing

Timed metadata in MPEG-4 can be packaged in standardized formats or proprietary binary structures:

  • MPEG-4 Timed Text / Streaming XML: Encapsulates human-readable or structured data directly correlated to timecodes.
  • Binary Telemetry Streams: Encodes high-frequency sensor readings (such as NMEA sentences or binary structures) directly into discrete byte arrays per sample.

During playback or processing, the demuxer reads the index tables in the moov atom, extracts the raw metadata samples from the mdat container simultaneously with the audio/video packets, and passes them to the application layer. The consuming application uses the shared timestamps to overlay maps, speedometers, or telemetry graphics in exact synchronization with the rendered video frames.

MP4 Alternate Language Tracks via Track Groups

The MPEG-4 container format, based on the ISO Base Media File Format (ISOBMFF), uses structural metadata boxes to package and manage multiple alternative language tracks within a single file. By pairing language metadata with grouping mechanisms—traditionally the alternate_group field in track headers and modernly the Track Group Box (trgr)—the container allows media players to identify related audio or subtitle streams, present available languages to the user, and switch dynamically between mutually exclusive alternatives without stream disruption.

Track Structure in MPEG-4 Containers

An MPEG-4 (MP4) file organizes media into a hierarchical tree of objects called "boxes" or "atoms." Media tracks are stored inside the Movie Box (moov), where each individual stream (video, audio, subtitles) is encapsulated in its own Track Box (trak).

When multiple audio languages are included (such as English, Spanish, and French dubs), each language is encoded as a separate trak entry. To prevent media players from decoding and playing all audio tracks simultaneously, the container uses grouping mechanisms to mark them as alternative versions of the same content.

Traditional Track Grouping: alternate_group

The primary and most widely supported mechanism for grouping alternative languages is the alternate_group field located inside the Track Header Box (tkhd).

  • Grouping Identifier: The alternate_group field contains a 16-bit integer. All tracks that share the same non-zero integer belong to the same alternative group.
  • Mutual Exclusivity: When tracks share an alternate_group ID, the demuxer or media player treats them as mutually exclusive alternatives. Only one track from a given group should be decoded and rendered at any single time.
  • Independent Tracks: A track with an alternate_group value of 0 indicates that it has no alternatives and can play independently (common for standard primary video tracks).

Advanced Grouping: The Track Group Box (trgr)

Modern specifications of the ISOBMFF standard introduce the Track Group Box (trgr), placed directly inside the trak box. This provides a more extensible grouping system than the simple alternate_group integer:

  1. TrackGroupTypeBox: Contained inside trgr, this box defines the specific relationship between grouped tracks using a 4-character identifier (fourcc).
  2. track_group_id: Assigns an integer ID to tie related tracks together under a specific relationship type.
  3. Advanced Relationships: Beyond simple language selection, trgr can define multi-source synchronization (msrc), audio descriptions for the visually impaired grouped with main dialogue, or multi-view video alternatives.

Language Identification Metadata

For alternative grouping to be functional, each track must explicitly declare its language so the playback engine can choose the correct stream automatically based on system preferences. This is achieved via two main boxes:

  • Media Header Box (mdhd): Contains a packed ISO 639-2/T 3-letter language code specifying the primary language of the track stream.
  • Extended Language Tag Box (elng): An optional box inside the Media Information Box (minf) or User Data Box (udta) that provides full IETF BCP 47 language tags (e.g., en-US, es-419, zh-Hans), allowing more granular regional language specification.

Playback Demuxing and Selection Process

When an MPEG-4 parser opens a file with multiple language tracks, it follows a deterministic selection process:

  1. Scan Headers: The parser reads all trak boxes inside the moov container and checks the tkhd and trgr boxes to map out available track groups.
  2. Group Identification: Tracks sharing an alternate_group ID or a language-based trgr ID are categorized as audio alternatives.
  3. Locale Matching: The player inspects the mdhd or elng boxes for each track in the group and compares them against the user's preferred audio language settings.
  4. Track Activation: The player sets the flags field in the selected track's tkhd to enabled (playback active) and disables the remaining alternative tracks in that group.
  5. Dynamic Switching: If the user selects a different language during playback, the player demuxer switches its read pointer to the corresponding sample tables (stbl) of the newly selected track within the same group, maintaining synchronization with the video timeline.

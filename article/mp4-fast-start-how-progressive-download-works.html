MP4 Fast Start: How Progressive Download Works

MP4 Fast Start enables immediate media playback during a download by restructuring the internal container hierarchy of an MPEG-4 file. By default, video encoders place the metadata required for decoding at the end of the file, forcing users to wait for a complete download before playback can begin. Applying the Fast Start modification moves this critical metadata to the beginning of the file and recalculates all internal byte offsets, allowing media players to immediately parse, decode, and render video frames as data arrives over HTTP progressive download.

The MP4 Box Architecture

The MPEG-4 (ISO Base Media File Format) structure is organized into hierarchical data blocks called "atoms" or "boxes." Three primary boxes dictate file playback:

  • ftyp (File Type Box): Identifies the file specifications, compatibility, and container brand.
  • mdat (Media Data Box): Contains the raw, interleaved audio and video payloads (the actual encoded frames). This is typically the largest component of the file.
  • moov (Movie Box): Contains all structural metadata, including codec details, resolution, duration, track definitions, and indexing tables that map specific timestamps to exact byte locations within the mdat box.

The Default Sequential Encoding Problem

During standard recording or encoding, a software encoder processes video frames sequentially and writes them immediately to the mdat box. Because the final sizes, durations, and byte offsets of all frames are not known until encoding completes, the encoder builds and appends the moov box at the very end of the file.

When a standard web browser or media player requests this file via standard HTTP progressive download, it reads the data sequentially from byte zero. Without the moov box, the player cannot determine frame rates, codec profiles, or where individual video packets begin. Consequently, playback cannot start until the entire file finishes downloading and the trailing moov box is read.

The Fast Start Structural Modifications

To enable Fast Start (also referred to as "web-optimized" encoding), two critical modifications are made to the binary structure:

  1. Relocating the moov Box: The moov atom is physically shifted from the end of the file to the front, positioning it immediately after the ftyp box and directly before the mdat box.
  2. Patching Chunk Offsets (stco / co64): Inside the moov box, sample table atoms (stbl) contain either a 32-bit stco (Sample Table Chunk Offset) atom or a 64-bit co64 atom. These tables store absolute byte positions pointing to each media chunk inside the mdat box. Moving the moov box to the front shifts the starting byte address of the mdat payload forward by the exact size of the moov box. Therefore, the Fast Start process recalculates and overwrites every offset in the stco or co64 tables to match the new byte locations.

How Fast Start Enables Immediate Playback

With the moov box located at the start of the byte stream, the media player downloads the essential playback index in the first few kilobytes of the transfer. The player instantly reads the codec parameters, initializes hardware decoders, references the updated chunk offset tables, and begins playing the video frames as they stream into the mdat payload without needing to download the rest of the file.

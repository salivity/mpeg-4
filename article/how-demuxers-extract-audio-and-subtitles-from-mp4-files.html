How Demuxers Extract Audio and Subtitles from MP4 Files

Demuxing (short for demultiplexing) is the software process of separating interleaved video, audio, and subtitle streams from a single container file into distinct, individual components. An MPEG-4 (MP4) file does not store media as a single combined blob, but rather as distinct, indexed streams wrapped inside a standard container format. Demuxing software reads the structural metadata of the MP4 container, maps the precise physical locations of the audio and subtitle data packets, and extracts them into separate files without decompressing or re-encoding the underlying data.

1. Parsing the MP4 Box Hierarchy

An MP4 file is structured around hierarchical data blocks called "boxes" or "atoms." When a demuxer opens an MP4 file, its first task is to locate and read the moov (movie metadata) box. The moov box contains no raw media data itself; instead, it acts as a table of contents that outlines every track contained within the file.

Within the moov box, the demuxer scans for individual trak (track) boxes. Each track represents a separate stream:

  • Audio tracks are identified by the handler type soun inside the hdlr (handler reference) box.
  • Subtitle or timed text tracks are identified by handler types such as sbtl, text, or subt.

2. Reading the Track Index Tables

Once the demuxer identifies the target audio or subtitle track, it traverses to the stbl (sample table) box located inside that specific track's hierarchy. The sample table contains the precise indexing information required to locate raw samples stored elsewhere in the file:

  • stsd (Sample Description): Identifies the codec used (e.g., AAC, Opus, ALAC for audio; TX3G or WebVTT for subtitles) and initialization parameters.
  • stts (Time-to-Sample): Maps timestamps and durations to each sample, preserving synchronization.
  • stsz (Sample Size): Defines the exact byte size of every individual sample.
  • stco or co64 (Chunk Offset): Provides the absolute byte offsets where groups of samples (chunks) are physically located on the storage medium.

3. Extracting Data from the Media Data Box

The actual encoded audio frames and subtitle text payloads reside in the mdat (media data) box. Because the video, audio, and subtitle packets in an MP4 are interleaved (mixed together sequentially to allow smooth streaming and playback), the raw media data cannot simply be read linearly.

The demuxer uses the offset tables (stco/co64) and size tables (stsz) gathered from step 2 to perform random file reads:

  1. It jumps directly to the byte address of an audio or subtitle chunk inside the mdat box.
  2. It reads the designated number of bytes representing that specific frame or subtitle entry.
  3. It skips over all interleaved video data packets entirely.

4. Reconstructing the Output Stream

After reading the raw frames, the demuxing software repackages the payload based on the requested output format:

  • For Audio: The software writes the extracted codec frames (such as AAC) into an appropriate stream header (like ADTS for .aac files) or places the raw audio stream into a new, single-stream container (such as .m4a or .wav).
  • For Subtitles: The software converts internal MP4 subtitle structures (like tx3g/mov_text) into standard text-based formats (like .srt or .vtt) by reading the text strings and calculating the start and end timestamps using the stts duration table.

Because this process only reads and reorganizes the existing compressed payloads, demuxing is a lossless operation that completes in a fraction of the time required for transcoding.

Purpose of stco and co64 Boxes in MP4 Files

The Chunk Offset box—identified by the four-character codes stco for 32-bit offsets and co64 for 64-bit offsets—is an essential metadata component in the MPEG-4 (ISOBMFF) file structure. Its primary purpose is to provide an index of absolute file offsets pointing to the beginning of each chunk of raw media data. This article explores how these boxes function within the MP4 container hierarchy, why they are necessary for media playback and seeking, and the differences between the 32-bit and 64-bit implementations.

Role in the ISO Base Media File Format Hierarchy

In the MPEG-4 container specification, metadata is stored in a structured tree of boxes (or "atoms"). The Chunk Offset box resides inside the Sample Table box (stbl), which is nested within the Media Information (minf), Media (mdia), Track (trak), and Movie (moov) boxes:

moov ➔ trak ➔ mdia ➔ minf ➔ stbl ➔ stco / co64

The actual raw audio and video data is stored in the Media Data box (mdat). Instead of referencing each individual media sample by its file position, the format groups adjacent samples into "chunks" to reduce the metadata overhead. The Chunk Offset box records the byte position of each chunk relative to the start of the entire file.

How Chunk Offsets Enable Sample Localization

To decode a specific frame or audio packet, a media player uses several complementary tables in the stbl box:

  1. Time-to-Sample (stts): Determines which sample corresponds to a specific timestamp.
  2. Sample-to-Chunk (stsc): Identifies which chunk contains that specific sample and how many samples are in that chunk.
  3. Chunk Offset (stco / co64): Provides the exact starting byte position of the target chunk in the file.
  4. Sample Size (stsz / stz2): Defines the byte size of each sample within the chunk to calculate the precise offset of the individual frame.

By cross-referencing these tables, the player can compute the exact byte range to read from disk or over the network without scanning through the entire mdat payload.

The Difference Between stco and co64

  • stco (Standard Chunk Offset Box): Uses 32-bit unsigned integers to store byte offsets. It is the default choice for standard MP4 files, but it limits the maximum offset to 4 gigabytes (\(2^{32} - 1\) bytes).
  • co64 (Chunk Large Offset Box): Uses 64-bit unsigned integers to store byte offsets. It was introduced to support files larger than 4 GB, allowing media files to scale into multi-terabyte sizes without indexing limitations.

A track can contain either an stco box or a co64 box, but never both simultaneously.

Importance in Media Seeking and Streaming

Because the stco and co64 boxes contain absolute file offsets, any modification that shifts the position of the mdat box—such as moving the moov box to the beginning of the file for web streaming (known as "Fast Start")—requires recalculating and rewriting all offset values in the Chunk Offset table. Without accurate chunk offsets, decoders cannot find or parse the media streams, resulting in playback failure.

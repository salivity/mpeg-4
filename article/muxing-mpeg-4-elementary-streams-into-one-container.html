Muxing MPEG-4 Elementary Streams into One Container

Multiplexing (muxing) independent MPEG-4 elementary streams involves combining distinct, raw audio, video, and data tracks into a single, synchronized container format such as MP4, MKV, or MPEG-TS. This article provides a straightforward breakdown of how these separate streams are parsed, synchronized using timing metadata, interleaved, and packaged into a standard media container without re-encoding the original media data.

Understanding Elementary Streams

An Elementary Stream (ES) is the raw output of an audio or video encoder containing only the payload data and minimal stream-specific headers. For MPEG-4, typical elementary streams include:

  • Video: MPEG-4 Part 2 (Visual) or MPEG-4 Part 10 (AVC/H.264), typically formatted as raw .m4v, .h264, or Annex B byte streams.
  • Audio: Advanced Audio Coding (AAC), typically structured with ADTS (Audio Data Transport Stream) headers or as raw .aac payloads.
  • Subtitles/Timed Text: MPEG-4 Part 17 (3GPP Timed Text) or similar text-based tracks.

Because elementary streams lack global timing references, index tables, and stream association markers, media players cannot reliably synchronize or seek through them simultaneously without a container.

The Step-by-Step Muxing Process

1. Stream Parsing and Validation

The multiplexer reads the input elementary streams to identify codec configurations and format properties:

  • Video: Identifies Sequence Parameter Sets (SPS), Picture Parameter Sets (PPS), framerate, resolution, and pixel aspect ratio.
  • Audio: Identifies sample rate, channel count, and codec profile (e.g., AAC-LC).

This data is extracted to build the container's configuration records (such as the avcC or esds boxes in an MP4 file).

2. Packetization and Timestamp Assignment

Each raw media unit (frame or sample) is assigned timing metadata to ensure proper synchronization during playback:

  • Decoding Time Stamp (DTS): Dictates the exact moment the decoder must decompress a frame. This is crucial for video formats utilizing B-frames (bi-directional predictive frames), where decoding order differs from display order.
  • Presentation Time Stamp (PTS) / Composition Time: Dictates the exact moment the frame must be rendered on screen.
  • Audio Packets: Audio frames generally have identical DTS and PTS values because audio decoding is linear.

3. Interleaving

The muxer arranges chunks of video, audio, and subtitle packets sequentially into a single data stream. Instead of placing all video data first and all audio data second, the muxer alternates small segments of audio and video (e.g., 0.5 to 1 second of audio followed by the corresponding duration of video). Interleaving ensures that the media player's buffer receives synchronized packets concurrently, minimizing memory overhead and preventing playback stutter.

4. Header and Metadata Construction

The container architecture requires index tables and metadata structures so players can navigate the file:

  • Sample Tables: Constructing indices that map presentation timestamps to specific byte offsets in the file (e.g., stts, stsc, and stco tables in MP4).
  • Keyframe Indexes: Identifying random access points (IDR / I-frames via the stss sync sample box) to enable seeking.
  • Track Headers: Defining track IDs, language tags, volume settings, and display dimensions.

5. Output Writing and Finalization

The multiplexer writes the physical container file:

  • Data Payload: The interleaved media packets are written to the main data segment (e.g., the mdat box in MP4).
  • Index Metadata Placement: In standard MP4 files, the metadata header (the moov atom) is written either at the end of the file or shifted to the beginning (fast-start) to enable progressive streaming over the web.

Practical Muxing Example

In real-world workflows, command-line tools execute this process losslessly using stream copying:

Using FFmpeg:

ffmpeg -i video.h264 -i audio.aac -c:v copy -c:a copy output.mp4

Using MP4Box (GPAC):

MP4Box -add video.h264 -add audio.aac -new output.mp4

Both tools extract the raw packets, compute the required time scales and byte offsets, and write the compliant MP4 container structure without altering the underlying compressed data.

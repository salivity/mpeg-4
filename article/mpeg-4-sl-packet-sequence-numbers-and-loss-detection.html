MPEG-4 SL Packet Sequence Numbers and Loss Detection

The MPEG-4 Synchronization Layer (SL) provides a standardized framework for packetizing elementary streams and synchronizing audio, video, and metadata. To detect lost or out-of-order data during transmission, the MPEG-4 SL packet header uses configurable sequence number fields. This article explains how these sequence numbers are configured, formatted in the header, and evaluated by receiving decoders to identify missing packets.

Configuration via the SLConfigDescriptor

Unlike fixed-header transport protocols, the MPEG-4 SL packet header is highly customizable to minimize bandwidth overhead across diverse network environments. The structure and presence of header fields are established out-of-band or in metadata using the SLConfigDescriptor.

To enable packet sequence numbering, the descriptor defines:

  • usePacketSequenceNumber: A 1-bit flag indicating whether the packet sequence number field is present in the SL header.
  • packetSeqNumLength: A field specifying the exact bit-length (ranging from 0 to 32 bits) of the sequence number field.

If usePacketSequenceNumber is set to 1 and packetSeqNumLength is greater than 0, every SL packet generated for that elementary stream must include the sequence number field in its header.

The packetSequenceNumber Header Field

When enabled, the encoder inserts the packetSequenceNumber syntax element into the SL packet header.

Key characteristics of this field include:

  • Monotonic Incrementing: The encoder increments the sequence number by 1 for each successive SL packet belonging to the same elementary stream.
  • Modulo Arithmetic: The sequence number increments sequentially up to \((2^{\text{packetSeqNumLength}} - 1)\) and then rolls over to 0. For example, an 8-bit field increments from 0 to 255 before wrapping around.
  • Stream-Specific Scope: Sequence numbering is maintained independently for each elementary stream, ensuring that multiplexed audio, video, and control streams do not interfere with one another's continuity checks.

Identifying Missing Packets at the Receiver

The receiving terminal or decoder uses the packetSequenceNumber to verify the continuity of the incoming stream and detect loss through the following steps:

  1. State Tracking: The decoder maintains an internal counter of the expected sequence number, which is initialized by the sequence number of the first received packet.
  2. Gap Detection: Upon arrival of a new SL packet, the decoder compares the received packetSequenceNumber (\(S_{\text{received}}\)) against the expected value (\(S_{\text{expected}} = S_{\text{previous}} + 1\)).
  3. Loss Identification: If \(S_{\text{received}} > S_{\text{expected}}\) (accounting for bit-length modulo wrap-around), a discontinuity is detected. The difference indicates the exact number of missing SL packets: \[\text{Missing Packets} = (S_{\text{received}} - S_{\text{expected}}) \pmod{2^{\text{packetSeqNumLength}}}\]
  4. Error Handling: Once missing packets are identified, the decoder can initiate transport-level retransmission requests, apply error concealment algorithms, or discard damaged Access Units to prevent decoding artifacts.

Access Unit Sequence Numbers

In addition to packet-level tracking, the MPEG-4 SL specification supports an optional AUSequenceNumber field, configured via AUSeqNumLength. While packetSequenceNumber tracks individual SL packets (which may contain partial or fragmented data), the AUSequenceNumber tracks complete Access Units (such as entire video frames). This dual-level numbering enables decoders to differentiate between the loss of a single packet fragment and the loss of an entire structural frame.

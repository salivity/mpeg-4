CABAC State Engine in MPEG-4 Explained

Context-Adaptive Binary Arithmetic Coding (CABAC) in MPEG-4 Part 10 (H.264/AVC) achieves superior video compression by dynamically adapting to symbol statistics and encoding binary decisions with minimal redundancy. This article details the operational state engine behind CABAC’s binary arithmetic coder, breaking down its internal registers, finite-state probability modeling, lookup-table transitions, and renormalization process.

The Core Operational State Registers

The arithmetic coding engine in CABAC tracks the current coding interval using two primary 9-bit/10-bit internal registers:

  • Current Interval Range (codIRange): Represents the width of the current probability sub-interval, constrained to the range \([256, 511]\) during standard operation.
  • Code Offset / Lower Bound (codIOffset / codILow): In the decoder, codIOffset represents the value read from the bitstream that points to a position within the current interval. In the encoder, codILow represents the lower boundary of the interval.

The 64-State Probability Transition Engine

Instead of executing computationally expensive dynamic multiplications or divisions to estimate probabilities, CABAC uses a 64-state Finite State Machine (FSM) for each context model. Each context state consists of two properties:

  1. Probability State Index (pStateIdx): A 6-bit integer ranging from 0 to 63, representing a quantized estimate of the Least Probable Symbol (LPS) probability (\(p_{\text{LPS}}\)), spanning from approximately \(0.5\) down to \(0.01875\).
  2. Value of the Most Probable Symbol (valMPS): A 1-bit value (0 or 1) indicating which binary symbol is currently most likely.

When a bin is processed, the state transitions deterministically using precalculated lookup tables:

  • MPS Transition (transIdxMPS): If the coded bin matches valMPS, the probability index increases toward higher confidence using the rule: \[\text{pStateIdx}_{\text{new}} = \text{transIdxMPS}[\text{pStateIdx}]\]
  • LPS Transition (transIdxLPS): If the coded bin matches the LPS, the confidence drops: \[\text{pStateIdx}_{\text{new}} = \text{transIdxLPS}[\text{pStateIdx}]\] If pStateIdx is already 0 and an LPS occurs, the valMPS bit is inverted (\(1 - \text{valMPS}\)), reflecting a flip in symbol dominance.

Multiplication-Free Interval Subdivision

To split codIRange into sub-ranges for the MPS and LPS without runtime multiplication, the engine utilizes a 2D lookup table called rangeTabLPS[64][4].

  1. The current codIRange is quantized into one of 4 discrete grid points by extracting its 2 most significant fractional bits: \[\text{qCodIRangeIdx} = (\text{codIRange} \gg 6) \ \& \ 3\]
  2. The sub-interval for the LPS (rLPS) is retrieved directly from the table: \[\text{rLPS} = \text{rangeTabLPS}[\text{pStateIdx}][\text{qCodIRangeIdx}]\]
  3. The remaining sub-interval belongs to the MPS: \[\text{rMPS} = \text{codIRange} - \text{rLPS}\]

Based on whether the bin is an MPS or LPS, the engine updates codIRange and shifts the base interval offset accordingly.

Renormalization Engine

Whenever codIRange falls below 256 (\(2^8\)), precision must be restored to prevent underflow. The renormalization engine executes an iterative bit-shift loop:

  • codIRange is left-shifted by 1 bit (codIRange <<= 1).
  • In the encoder, output bits (and any accumulated outstanding bits) are pushed to the bitstream as the base interval expands.
  • In the decoder, codIOffset is left-shifted by 1 bit and the next bit from the bitstream is appended to its least significant position.
  • The loop continues until codIRange reaches or exceeds 256.

Specialized Operational Modes

The CABAC engine also contains two streamlined operational paths alongside standard context-coded bins:

  • Bypass Mode: For uniformly distributed data (e.g., sign bits, residual suffixes), context modeling is bypassed. The engine divides codIRange in half with a single right shift (>> 1), halving the cycle cost.
  • Terminate Mode: Used for end-of-slice signaling and macroblock termination flags, allocating a fixed narrow interval for the terminate symbol to trigger bitstream flushing.

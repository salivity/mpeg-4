Fix Broken MP4 Keyframe Indices With Open Source Tools

Broken keyframe indices in MPEG-4 (MP4) files prevent media players from seeking smoothly, cause playback stutter, or render the video completely unplayable. This guide outlines how to repair and rebuild corrupted index tables, headers, and keyframes using powerful, free, and open-source command-line utilities including FFmpeg, MP4Box, and Untrunc.

Method 1: Re-muxing with FFmpeg

In many cases, the video streams are intact, but the index chunk (the moov atom) or the seek table (stss box) is misaligned. Re-muxing regenerates the index table without re-encoding the actual audio and video data.

Run the following command in your terminal:

ffmpeg -err_detect ignore_err -i corrupted_input.mp4 -c copy -movflags +faststart repaired_output.mp4
  • -err_detect ignore_err: Forces FFmpeg to bypass minor container corruption.
  • -c copy: Duplicates the audio and video streams without transcoding, preserving original quality.
  • -movflags +faststart: Relocates the newly rebuilt index to the beginning of the file for optimized seeking and streaming.

Method 2: Rebuilding Container Atoms with MP4Box

MP4Box (part of the GPAC multimedia framework) interacts directly with MP4 container structures and can extract raw tracks to build a fresh sample table.

  1. Extract and Re-multiplex Tracks: 
    mp4box -add corrupted_input.mp4#video -add corrupted_input.mp4#audio -new repaired_output.mp4
  2. Flatten the File Structure: If the file still fails to seek, force MP4Box to rewrite the file layout: 
    mp4box -flat repaired_output.mp4

Method 3: Restoring Truncated Files with Untrunc

If an MP4 recording was interrupted (due to a power failure or crash), the keyframe index might not have been written at all. untrunc can restore the missing index by copying the atom structure from a healthy reference file recorded with the same device and settings.

  1. Install and run untrunc: 
    untrunc healthy_reference.mp4 corrupted_input.mp4
  2. The tool analyzes the healthy file's codec parameters and sample tables, reconstructs the missing packet boundaries, and outputs corrupted_input.mp4_fixed.mp4.

Method 4: Forcing New Keyframes via Re-encoding

If the underlying video stream has damaged keyframe (I-frame) headers that cannot be resolved through container re-muxing, you must re-encode the stream to generate fresh intra-frames at fixed intervals.

Execute the following command:

ffmpeg -i corrupted_input.mp4 -c:v libx264 -crf 18 -g 60 -keyint_min 60 -sc_threshold 0 -c:a copy repaired_output.mp4
  • -g 60: Enforces a maximum Group of Pictures (GOP) size, inserting a keyframe every 60 frames.
  • -keyint_min 60 and -sc_threshold 0: Disables dynamic scene-cut detection to ensure deterministic, equidistant keyframe placement across the timeline.
  • -crf 18: Applies visually lossless video quality.
  • -c:a copy: Leaves the audio stream uncompressed to speed up processing.

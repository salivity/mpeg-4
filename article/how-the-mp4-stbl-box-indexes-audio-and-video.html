How the MP4 stbl Box Indexes Audio and Video

The Sample Table box (stbl) acts as the central indexing directory for media tracks inside an MPEG-4 (MP4 / ISOBMFF) container. Rather than scattering metadata across the media payload, an MP4 file stores raw audio and video data in the Media Data box (mdat) and uses the sub-boxes inside stbl to map every frame's exact timing, size, file offset, and keyframe status. This design allows media players to seek instantly to any point in a track, calculate byte locations without parsing the raw stream, and properly synchronize audio with video.

Core Sub-Boxes of the stbl Hierarchy

The stbl box resides inside the moov.trak.mdia.minf hierarchy and contains several dedicated sub-tables, each responsible for a distinct indexing property:

  • Sample Description Box (stsd): Defines the codec (such as H.264, HEVC, AAC) and initialization parameters (width, height, color space, audio sample rate) required to decode the samples in this track.
  • Time-to-Sample Box (stts): Maps sample numbers to their decoding durations (Decode Time Stamp, or DTS). It compresses this mapping by grouping consecutive frames that share the same delta duration.
  • Composition Time to Sample Box (ctts): Used when video contains out-of-order frames (such as B-frames). It stores the offset between a frame's decode timestamp (DTS) and its presentation timestamp (PTS).
  • Sync Sample Box (stss): Lists the sample numbers that are keyframes (I-frames/IDR-frames). Media players query this table when seeking so playback can start from an independently decodable frame.
  • Sample-to-Chunk Box (stsc): Groups samples into larger blocks called "chunks." This table maps ranges of chunks to the number of samples they contain and links them to their corresponding description in stsd.
  • Sample Size Box (stsz / stz2): Lists the exact size in bytes of every individual sample, or specifies a single uniform size if all samples are identical.
  • Chunk Offset Box (stco / co64): Contains the absolute byte offset from the start of the file to the beginning of each chunk (stco uses 32-bit pointers; co64 uses 64-bit pointers for files larger than 4 GB).

How a Player Locates a Frame: Step-by-Step

When a media player needs to retrieve a video frame or audio packet at a target playback timestamp, it traverses the stbl tables in a sequential lookup:

  1. Timestamp to Sample Number: The player calculates the target decode time and consults stts (and ctts if present) to determine the exact sample index \(N\).
  2. Keyframe Adjustment (Seeking): If seeking, the player checks stss to find the nearest keyframe index equal to or preceding sample \(N\).
  3. Sample to Chunk Mapping: The player searches stsc to find which chunk contains sample \(N\), as well as the position of sample \(N\) relative to the start of that chunk.
  4. Chunk Offset Lookup: The player looks up the target chunk in stco (or co64) to retrieve the absolute byte offset of the chunk within the MP4 file.
  5. Exact Byte Calculation: The player consults stsz to sum the byte lengths of all samples within the same chunk that precede sample \(N\). Adding this sum to the chunk's base offset yields the exact starting byte address and length of sample \(N\) inside the mdat container.

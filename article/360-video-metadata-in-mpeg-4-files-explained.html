360 Video Metadata in MPEG-4 Files Explained

MPEG-4 (MP4) files store spatial metadata for 360-degree immersive video through dedicated data structures embedded directly within the container format's hierarchy. By utilizing specialized metadata boxes—historically user-defined uuid atoms containing XML schemas, and more recently standardized sv3d (Spherical Video) boxes defined by ISO/IEC specifications—video players are instructed how to project flat, equirectangular or cubemap video frames onto a 3D spherical viewport for real-time immersive playback.

The ISO Base Media File Format (ISOBMFF) Structure

The MP4 format is derived from the ISO Base Media File Format (ISOBMFF), which organizes all video, audio, and metadata into discrete hierarchical blocks called "boxes" (or "atoms"). Each box consists of a header specifying its size and a four-character code (FourCC) identifying its type. Because ISOBMFF is modular, additional information about projection, camera orientation, and stereoscopic geometry can be attached to the video stream without disrupting standard decoding pipelines.

The Spatial Media XML and uuid Box

The initial industry standard for 360-degree video metadata was introduced via Google's Spatial Media specification. Under this implementation, spatial metadata is encoded as an RDF-compliant XML block and inserted into a custom user-data box (uuid) located inside the movie header (moov) or video track (trak) box.

This XML block provides critical rendering parameters, including:

  • Spherical: A boolean flag confirming the presence of spherical video.
  • Stitched: Indicates whether the video frames have already been stitched together into a single panoramic projection.
  • ProjectionType: Defines the geometric projection format, most commonly equirectangular.
  • StereoMode: Specifies whether the video is monoscopic, top-bottom stereoscopic, or left-right stereoscopic.
  • Initial View Orientation: Declares the default yaw, pitch, and roll angles to establish the initial viewing direction for the user.

Standardized sv3d Spherical Video Box

To standardize omnidirectional video, the Moving Picture Experts Group (MPEG) developed formal extensions under ISO/IEC 14496-12 and ISO/IEC 23090-2 (Omnidirectional MediA Format, or OMAF). In this standardized approach, spatial metadata is encapsulated within the sv3d (Spherical Video Box), which resides inside the Sample Description Box (stsd) of the video track.

The sv3d container includes specific sub-boxes:

  • svhd (Spherical Video Header): Contains high-level properties, including metadata versioning.
  • proj (Projection Box): Encapsulates the specific mathematical mapping applied to the video frame, containing further child boxes such as eqrp (Equirectangular Projection) or cbmp (Cubemap Projection).
  • pose (Pose Box): Defines orientation adjustments via yaw, pitch, and roll rotation values relative to the world coordinate system.

Playback Execution

When a media player or WebGL renderer opens the MP4 file, it parses the box hierarchy before decoding the pixel data stored in the media data box (mdat). If the player detects the sv3d box or the spatial media uuid atom, it bypasses traditional planar 2D display pipelines. Instead, it maps the decoded 2D frames onto a virtual 3D mesh (such as a UV sphere or cube) and positions the virtual camera at the center of the geometry, updating the rendered field of view in response to user head movement or mouse interactions.

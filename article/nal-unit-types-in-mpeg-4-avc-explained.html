NAL Unit Types in MPEG-4 AVC Explained

In MPEG-4 Part 10 (H.264/AVC), the Network Abstraction Layer (NAL) encapsulates video data into self-contained units. The NAL unit distinguishes between parameter sets, video slices, and Supplemental Enhancement Information (SEI) using a dedicated 5-bit identifier located in the NAL unit header. This mechanism allows decoders and network devices to quickly categorize incoming packets as configuration metadata, timing/enhancement information, or raw video content without needing to parse the full payload.

The NAL Unit Header Structure

Every NAL unit begins with a 1-byte (8-bit) header defined by the standard. This byte is divided into three distinct syntax elements:

  1. forbidden_zero_bit (1 bit): Must always be 0. A value of 1 indicates a syntax violation or bit error.
  2. nal_ref_idc (2 bits): Indicates the priority and whether the unit is referenced by other frames (values greater than 0 mark reference data, while 00 marks non-reference data).
  3. nal_unit_type (5 bits): Specifies the exact type of payload contained in the NAL unit.

By evaluating the lower 5 bits (nal_unit_type = byte & 0x1F), the decoder determines the data classification, covering integer values from 0 to 31.

Categorizing Payloads by NAL Unit Type

The standard groups these 5-bit integer values into Video Coding Layer (VCL) data, parameter sets, and non-VCL metadata.

1. Parameter Sets (Types 7 and 8)

Parameter sets carry global configuration settings that rarely change across frames. Rather than repeating configuration parameters in every slice, slices reference these sets by an ID.

  • Type 7 (Sequence Parameter Set - SPS): Contains stream-level parameters applicable to an entire video sequence, such as profile, level, frame dimensions, aspect ratio, and video format.
  • Type 8 (Picture Parameter Set - PPS): Contains picture-level parameters applicable to one or more frames, such as entropy coding mode (CABAC/CAVLC), slice group definitions, and quantization parameters.

2. Coded Slices (Types 1 through 5)

Slices represent the actual compressed macroblock data (VCL data) used to reconstruct the video image.

  • Type 1 (Non-IDR Slice): Contains slice data for predicted frames (P-frames, B-frames, or non-instantaneous refresh I-frames).
  • Types 2, 3, and 4 (Data Partitioning A, B, and C): Used when slice data partitioning is enabled to separate header data from intra and inter texture coefficients.
  • Type 5 (IDR Slice): Represents an Instantaneous Decoding Refresh frame. Decoding an IDR slice completely clears the reference picture buffer, ensuring no subsequent frames depend on frames prior to the IDR.

3. SEI Data (Type 6)

Supplemental Enhancement Information provides optional metadata that assists with decoding, display, or timing without being necessary to reconstruct the basic video samples.

  • Type 6 (SEI): Carries timecodes, picture structure details, mastering display color volume (HDR data), closed captions, and buffer management messages. If a decoder does not support or require a specific SEI message, it can safely discard Type 6 units.

Decoder Handling Workflow

When an MPEG-4 stream is processed:

  1. Parsing: The transport layer extracts the 1-byte header of the incoming NAL unit.
  2. Filtering: Network routers or decoders evaluate nal_unit_type. Non-critical data (like Type 6 SEI) or low-priority units (nal_ref_idc == 0) can be dropped during network congestion without breaking core video decoding.
  3. State Configuration: If Types 7 (SPS) or 8 (PPS) arrive, the decoder stores the configurations in memory.
  4. Reconstruction: When Types 1 or 5 arrive, the decoder fetches the referenced PPS/SPS settings and decodes the pixel data for the active frame.

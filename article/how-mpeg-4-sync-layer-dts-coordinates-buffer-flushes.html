How MPEG-4 Sync Layer DTS Coordinates Buffer Flushes

The Decoding Time Stamp (DTS) in the MPEG-4 Sync Layer (SL) serves as a critical synchronization mechanism that dictates precisely when an Access Unit (AU) must be removed from the decoding buffer and handed over to the decoder. In streaming and playback pipelines, the coordination between the DTS, system clocks, and buffer management ensures deterministic pipeline buffer flushes during normal playback, stream discontinuities, and random access events. This article explains how the Sync Layer uses DTS to govern buffer management and synchronize pipeline clearing operations.

The Sync Layer Timing Framework

The MPEG-4 Systems specification (ISO/IEC 14496-1) defines the Sync Layer to adapt elementary streams into time-stamped packet sequences. Within this layer, each Access Unit is packetized into one or more SL packets that carry timing metadata, primarily the Decoding Time Stamp (DTS), the Composition Time Stamp (CTS), and Object Clock Reference (OCR) values.

The MPEG-4 decoding architecture relies on a generalized conceptual buffer model consisting of:

  • The Channel Buffer / Delivery Layer: Receives incoming data from the transport mechanism.
  • The Decoding Buffer (DB): Stores SL packets and reassembles them into complete Access Units awaiting decoding.
  • The Composition Buffer (CB): Retains decoded frames until their presentation time (CTS).

The DTS explicitly defines the instantaneous time instant relative to the active OCR at which the entirety of an AU must be extracted from the Decoding Buffer and passed to the elementary stream decoder.

DTS-Driven Buffer Extraction and Normal Pipeline Draining

Under steady-state conditions, the Decoding Buffer operates according to the DTS schedule. The decoding pipeline coordinates buffer emptying via the following process:

  1. Reassembly: Incoming SL packets populate the Decoding Buffer until a complete AU is formed.
  2. Clock Comparison: The Sync Layer continuously compares the local Elementary Stream time derived from the OCR to the DTS of the head-of-line AU in the Decoding Buffer.
  3. Instantaneous Evacuation: When the OCR reaches the value specified by the DTS, the Sync Layer instantaneously pulls that AU out of the Decoding Buffer.

This strict schedule prevents both buffer overflow (data arriving faster than extraction) and underflow (extraction triggered before data is fully assembled).

Coordinating Buffer Flushes During Discontinuities

A buffer flush is required when the continuous temporal flow is interrupted—such as during seeking, track switching, stream splicing, or error recovery following packet loss. In these scenarios, the Sync Layer coordinates the flush using the DTS in conjunction with specific SL packet header flags:

1. Discontinuity Detection and Timeline Resets

When a stream discontinuity occurs, the Sync Layer receives a new reference time base (a new OCR value) and an AU marked with discontinuity indicators or a randomAccessPointFlag. The incoming AU carries a DTS that is not contiguous with the previous timeline.

2. Stale AU Invalidation

Upon identifying a timeline shift, the Sync Layer uses the new DTS boundary to coordinate the flush of stale data:

  • Any un-decoded AUs remaining in the Decoding Buffer whose DTS belongs to the previous reference timeline are invalidated.
  • The pipeline parser clears the pre-decoder queue up to the boundary of the AU carrying the new, valid DTS.
  • The Sync Layer drops partially reassembled AUs in the buffer to avoid passing corrupt or temporally misplaced payloads to the media decoder.

3. Post-Flush Decoder Alignment

Once the Decoding Buffer is cleared, the Sync Layer halts extraction until the newly received data fills the buffer sufficiently to meet the initial buffering delay. When the local clock matches the new DTS of the first incoming Random Access Point AU, the Sync Layer triggers decoder processing, effectively restarting the pipeline without visual or acoustic artifacts.

Through this mechanism, the DTS acts as both the schedule for standard buffer consumption and the temporal demarcation line used to clear, re-align, and restart the decoding pipeline during state transitions.

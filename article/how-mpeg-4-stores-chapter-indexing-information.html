How MPEG-4 Stores Chapter Indexing Information

MPEG-4 video containers enable chapter-based navigation through structured internal metadata and dedicated timed-text tracks. By referencing discrete timestamps alongside descriptive titles within the ISO Base Media File Format (ISOBMFF), MP4 files allow consumer playback devices and media software to display interactive chapter menus, jump to specific scenes, and improve overall content navigation without altering the core audio and video streams.

The ISO Base Media File Format Structure

The MP4 container format (MPEG-4 Part 14) is built on an object-oriented file structure made up of nested data blocks called "atoms" or "boxes." Each box contains a header specifying its size and type, followed by the payload data.

Video, audio, subtitles, and chapter markers are kept in distinct tracks (trak boxes) housed within the main movie box (moov). This modular structure allows navigation markers to exist alongside media data rather than being hardcoded into the video stream itself.

Timed Text Chapter Tracks (Apple Method)

The most widely adopted method for storing chapters in consumer MP4 files is the QuickTime-derived timed text format:

  1. Dedicated Text Track: A standard subtitle or text track (tx3g or generic text) is added to the container. Each sample within this track contains a UTF-8 or UTF-16 text string representing a chapter title.
  2. Sample Timing: The track’s sample table (stbl) specifies the exact start time and duration for each chapter title, synchronizing them with the video's presentation timeline.
  3. Track Reference (tref): To designate the text track as a chapter list rather than standard subtitles, a Track Reference box is added to the main video track. Inside tref, a chap reference links directly to the ID of the timed text track.

When a media player detects the chap reference in the video track, it suppresses the text from displaying as normal on-screen subtitles and instead populates the player's chapter selection menu.

Nero Chapter Lists (chpl Atom)

Another standard method, historically introduced by Nero software and supported by various open-source players, stores chapter data inside the user data box (udta):

  • The chpl Box: Located inside the moov or udta atom, the chpl box contains a simple list of entries.
  • Payload Format: Each entry consists of an absolute 64-bit timestamp (aligned with the movie timescale) and a string specifying the chapter name.
  • Self-Contained Metadata: Unlike track-referenced chapters, this method does not require a separate media track, making it lightweight, though less universally supported across hardware devices than the timed text method.

How Players Process Chapter Navigation

When a consumer opens an MP4 file:

  1. The player parses the moov atom header to map out the tracks and metadata.
  2. It looks for either a tref -> chap link or a chpl user data atom.
  3. The player constructs a timeline index matching each chapter’s timestamp to the nearest video keyframe (I-frame) defined in the Sync Sample box (stss).
  4. When a user selects a chapter, the playback engine immediately seeks to the corresponding keyframe, ensuring clean and instantaneous playback from that point.

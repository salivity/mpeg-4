MPEG-4 Stereoscopic 3D Layout Packing Explained

The MPEG-4 (MP4) file format stores stereoscopic 3D layout packing information using standardized container-level metadata boxes and video bitstream Supplemental Enhancement Information (SEI) messages. These mechanisms indicate how left-eye and right-eye visual channels are arranged within a single video frame or across separate streams. By embedding this structural metadata, the file informs decoders and display devices how to unpack and present the stereoscopic views correctly.

Container-Level Storage: The st3d Box

In the ISO Base Media File Format (ISOBMFF / MPEG-4 Part 12), stereoscopic packaging is formally defined at the container level through the Stereoscopic 3D Video Box (st3d).

  • Placement: The st3d box resides inside the Visual Sample Entry (located within the stsd sample description box inside the video track).
  • Syntax and Data: It contains a simple layout flag that explicitly declares the frame packing format:
    • 0x00: Monoscopic video (or unspecified).
    • 0x01: Side-by-Side (left and right views placed horizontally next to each other).
    • 0x02: Top-Bottom / Over-Under (left and right views placed vertically, one above the other).
    • 0x03: Row Interleaved (alternating horizontal lines for each eye).
    • 0x04: Column Interleaved (alternating vertical lines for each eye).
    • 0x05: Temporal Interleaved (sequential frames alternating between eyes).
  • View Ordering: An additional field specifies whether the left view or the right view comes first (e.g., left view on the left vs. left view on the right in a side-by-side configuration).

Codec-Level Storage: Frame Packing Arrangement SEI

When stereoscopic video is encoded using AVC/H.264 or HEVC/H.265 within an MP4 file, layout details are also embedded directly into the video stream using Frame Packing Arrangement (FPA) Supplemental Enhancement Information (SEI) messages.

  • FPA SEI Payload: Defined in ISO/IEC 14496-10 (AVC) and ISO/IEC 23008-2 (HEVC), this metadata block travels with video access units.
  • Layout Identification: The SEI message identifies the exact spatial arrangement (e.g., side-by-side, top-bottom, checkerboard) and whether subsampling or visual decimation was applied to fit both views into standard dimensions.
  • Color and Cropping Flags: The SEI data includes positioning flags, quincunx sampling configurations, and crop flags that instruct the decoder on how to crop or reconstruct each eye's native aspect ratio.

Multi-Track and Multi-View Coding (MVC / MV-HEVC)

In non-packed configurations where both views maintain full resolution in separate streams, MPEG-4 uses distinct track relationships:

  • Track References (tref): A secondary track containing the dependent/disparity view references the base view track using a track reference box with the reference type sbas (stereo base) or dpnd (dependency).
  • Sample Entries: Multi-View Video Coding (MVC) uses specific sample entries like mvc1 or encv, signaling to the demuxer that separate elementary streams must be decoded together to create the full stereoscopic pair.

Through these combined methods—the container's st3d box for high-level identification, bitstream SEI messages for decoder-level frame unpacking, and multi-track references for multi-view codecs—the MPEG-4 format provides a complete framework for storing and decoding 3D layout data.

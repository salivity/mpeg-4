Composition Time Stamp in MPEG-4 Sync Layer Explained

This article provides an overview of the Composition Time Stamp (CTS) within the MPEG-4 Synchronization Layer (SL) architecture. It explores the fundamental role of CTS in media playback, explains how it coordinates with the Decoding Time Stamp (DTS) for proper frame reordering, and details how the Sync Layer applies CTS to ensure seamless presentation timing and lip-sync across diverse audio-visual streams.

The MPEG-4 Synchronization Layer Overview

The MPEG-4 standard uses a flexible, object-based approach to multimedia. To manage disparate streams—such as audio, video, 3D graphics, and interactive scene descriptions—the MPEG-4 Systems architecture defines the Synchronization Layer (SL).

The SL wraps Elementary Streams (ES) into discrete SL packets. The primary duty of this layer is to provide temporal synchronization, stream identification, and packet continuity across independent elementary streams, independent of the underlying transport layer (such as RTP, MPEG-2 TS, or MP4 file structures).

Defining the Composition Time Stamp (CTS)

The Composition Time Stamp (CTS) is a dedicated timing field encapsulated within the SL packet header. Its primary role is to specify the exact instant—relative to an Object Time Base (OTB)—at which an Access Unit (AU), such as a decoded video frame or audio frame, must be presented or composed in the final scene.

While decoding systems operate on varying computational latencies, the CTS guarantees that the decoded output is rendered to the user at the mathematically correct chronological moment.

CTS vs. Decoding Time Stamp (DTS)

To understand CTS, it is essential to distinguish it from the Decoding Time Stamp (DTS):

  • Decoding Time Stamp (DTS): Indicates the exact time the decoder must process and decode the Access Unit from the decoding buffer.
  • Composition Time Stamp (CTS): Indicates the exact time the decoded composition unit must be displayed or mixed into the presentation.

In simpler media formats or bidirectional-frame-free streams (such as basic audio), the DTS and CTS values are identical. However, when advanced video compression techniques use bidirectional prediction (B-frames), frames must be transmitted and decoded out of display order. In these scenarios, the DTS directs the decoder to unpack reference frames first, while the CTS ensures those frames are reordered and rendered in the proper sequence for playback.

How CTS Operates within the SL Architecture

The Sync Layer manages CTS through several key mechanisms:

1. Time Base Mapping

Every elementary stream is tied to an Object Time Base (OTB), derived from a reference clock. The CTS expresses temporal values as a discrete count of clock ticks based on the configured resolution (SLConfigDescriptor.customTimeStampResolution).

2. Header Flexibility

To optimize network bandwidth, the MPEG-4 SL syntax allows the CTS to be transmitted in several configurable formats:

  • Full Instant Timestamp: Sent when reference points or random access points occur.
  • Delta Timestamp: Transmitted as a relative offset from the previous frame's timestamp.
  • Implicit Timestamp: Omitted entirely if the stream operates at a fixed, constant frame rate where the receiver can deterministically infer the next presentation time.

3. Inter-Stream Synchronization (Lip-Sync)

Because different elementary streams (e.g., an AAC audio stream and an MPEG-4 Visual stream) carry their own SL packet headers with their respective CTS entries, the MPEG-4 compositor uses these timestamps to align parallel streams. This prevents audio-video drift and maintains accurate synchronization between spoken audio, video display, and dynamic scene graphics (BIFS).

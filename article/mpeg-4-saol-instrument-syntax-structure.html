MPEG-4 SAOL Instrument Syntax Structure

This article provides a technical overview of how instrument definitions are structured in MPEG-4 Structured Audio Orchestra Language (SAOL). It details the core syntactic components of a SAOL instrument (instr), covering the declaration header, input parameters, variable rate typing, processing block, and output mechanisms.

General Syntax Template

In MPEG-4 SAOL, an instrument represents an audio synthesis or processing unit that is instantiated by score events or dynamic triggers. The basic grammar structure of an instrument definition is as follows:

instr instrument_name ( parameter_list ) {
    // 1. Variable Declarations (State and Signal Typing)
    ivar initialization_variable;
    ksig control_rate_variable;
    asig audio_rate_variable;
    table wavetable_reference;

    // 2. Instrument Body (Instructions and Expressions)
    // Initialization, control-rate, and audio-rate statements

    // 3. Signal Routing / Output
    output(audio_signal);
}

1. The Instrument Header and Parameters

The definition begins with the instr keyword, followed by a unique identifier and a parenthesized parameter list:

  • Keyword: instr signals the creation of an instrument block.
  • Name: A user-defined identifier used to reference the instrument in SASL score lines or MIDI triggers.
  • Parameter List: A comma-separated list of parameter identifiers passed at instantiation time (such as pitch, velocity, or duration). By default, parameters passed to the instrument are evaluated at initialization rate (i-rate).
instr SimpleSynth (pitch, velocity) { ... }

2. Variable Declarations and Rate Typing

SAOL relies on strict execution rates for digital signal processing. Inside the instrument block, all variables must be declared with their respective calculation rates before being used in expressions:

  • ivar (Initialization Rate): Evaluated only once when the instrument instance is created. Used for static setup, pre-calculated constants, and score parameter assignments.
  • ksig (Control Rate): Evaluated at the control rate (typically slower than audio rate, defined by krate). Used for envelopes, LFOs, and parameter modulation to conserve processing power.
  • asig (Audio Rate): Evaluated at the full sampling rate (srate). Used for audio signals, filters, and core oscillator outputs.
  • table: Declares a reference to a dynamic or static lookup table (such as a sine wave or sample map).
  • oparray: Declares an array of opcode instances when polyphonic or multi-stage sub-processes are required.

3. Execution Statements and Control Flow

Following the variable declarations, the instrument body contains standard assignment expressions, math operations, and control flow constructs:

  • Control Structures: Standard imperative loops and conditions, such as if-else and while, can be used to control data flow.
  • Core Opcodes: Built-in synthesis primitives (e.g., oscil, pluck, biquad, kline) generate and manipulate signals.
  • Global Access (imports / exports): Instruments can optionally import global variables or export their internal states to communicate with other instruments or effect buses.

4. Output and Termination

The instrument finishes processing by directing audio signals to specific audio output buses:

  • output(): Directs an asig or list of asig channels to the main sound card output or a declared routing bus.
  • turnoff / Duration Expiry: An instrument automatically terminates when its score-defined duration ends, or it can be manually halted using conditional logic.

Complete Code Example

Below is a complete, syntactically valid example of a basic tone generator defined in SAOL:

instr SineBeep (pitch, velocity) {
    ivar freq, amp;
    asig sound, env;
    table wavetable;

    // Convert MIDI pitch and velocity at i-rate
    freq = cpsmidi(pitch);
    amp = velocity / 127;

    // Generate linear envelope at audio rate
    env = aline(0, 0.05, amp, dur - 0.1, amp, 0.05, 0);

    // Generate sine tone using standard oscillator
    sound = oscil(wavetable, freq) * env;

    // Send the final signal to the global output
    output(sound);
}

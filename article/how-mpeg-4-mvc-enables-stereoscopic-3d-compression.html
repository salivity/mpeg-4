How MPEG-4 MVC Enables Stereoscopic 3D Compression

MPEG-4 Multiview Video Coding (MVC) is an extension of the H.264/MPEG-4 AVC standard designed to compress 3D stereoscopic and multiview video content efficiently. By leveraging the high visual similarity between the left-eye and right-eye perspectives alongside traditional temporal compression, MVC significantly reduces the bandwidth required for 3D video. This article explains the underlying mechanisms of MVC, focusing on inter-view prediction, base-view compatibility, and the resulting compression efficiencies that power Blu-ray 3D and other stereoscopic media.

The Foundation: Base View and Dependent View

Stereoscopic 3D video relies on delivering two slightly offset video streams: one for the left eye and one for the right eye. Instead of encoding both streams independently—which would double the required data rate—MVC organizes the content into a Base View and one or more Dependent Views.

  • Base View: This is typically the left-eye stream, encoded as standard 2D H.264/AVC video. It contains no MVC-specific references and is fully backward-compatible with standard 2D playback devices.
  • Dependent View: This is typically the right-eye stream, encoded using MVC-specific syntax. It relies on data from the base view to eliminate redundancy between the two visual channels.

Inter-View Prediction and Disparity Compensation

Traditional video compression uses temporal prediction (motion estimation and compensation) to exploit similarities between consecutive frames in time within a single video stream. MVC builds on this by introducing inter-view prediction, which exploits similarities between different views at the exact same point in time.

Because stereoscopic cameras record the same scene from slightly different horizontal angles, the left and right frames share almost identical visual content, differing primarily by horizontal shift (disparity). MVC uses disparity estimation and disparity compensation—algorithms mathematically similar to motion estimation—to calculate these spatial offsets. Instead of encoding the entire right-eye frame, the codec encodes only the disparity vectors and the residual error (the differences that cannot be predicted from the base view).

Combined Temporal and Inter-View Coding

MVC maximizes efficiency by allowing macroblocks in dependent views to reference both temporal and spatial dimensions. A frame in the dependent view can select its prediction references from:

  1. Preceding and succeeding frames in the same view (temporal motion prediction).
  2. The corresponding frame in the base view at the same time instance (inter-view disparity prediction).

The encoder evaluates which reference method yields the lowest bit cost for each block of pixels and applies the most efficient mode dynamically.

Efficiency and Backward Compatibility

Through inter-view prediction, MVC reduces the data overhead of the secondary stream significantly. Rather than requiring a 100% increase in bitrate to deliver two discrete video channels, MVC typically requires only a 40% to 60% bitrate increase over a standard 2D stream to deliver a full-resolution 3D experience.

Furthermore, legacy 2D decoders simply ignore the MVC enhancement layer and process the base view, ensuring seamless backward compatibility without requiring dual-format disc mastering or duplicate broadcasting streams.

How Track Fragment Header Box Defines Base Data Offsets

In fragmented MPEG-4 (fMP4) streaming, the Track Fragment Header box (tfhd) establishes the baseline byte offset used to locate raw audio and video samples within a Media Data box (mdat). This article explains the technical mechanisms tfhd uses to define base data offsets, including flag configurations, explicit offset signaling, and relative reference points essential for streaming protocols like HLS and MPEG-DASH.

The Role of tfhd in Fragmented MP4

In the ISO Base Media File Format (ISOBMFF), fragmented streams divide content into Movie Fragment boxes (moof) followed by Media Data boxes (mdat). Each moof contains one or more Track Fragment boxes (traf), which house a tfhd box. The primary role of tfhd is to define default metadata for the fragment's samples, most critically the base_data_offset from which sample byte positions in the Track Run box (trun) are calculated.

Explicit Base Data Offsets

A tfhd box explicitly defines a base data offset using its internal flags field:

  1. base-data-offset-present Flag (0x000001): When this flag is set in the tfhd header, an explicit 64-bit unsigned integer field named base_data_offset is included immediately following the track ID.
  2. Absolute File Positioning: The value of base_data_offset represents the absolute byte position from the beginning of the entire presentation or file to the reference point for sample data.

Implicit and Relative Offsets

When the base-data-offset-present flag is omitted, parsers determine the base data offset implicitly using standard fallback rules:

  • default-base-is-moof Flag (0x020000): Introduced in later revisions of ISO/IEC 14496-12 and standard in CMAF (Common Media Application Format), this flag explicitly instructs the demuxer to set the base data offset to the first byte of the enclosing moof box. This enables independent segment processing and simplifies live stream stitching.
  • Default Fallback (Neither Flag Present): If neither base-data-offset-present nor default-base-is-moof is set, the base data offset defaults to the start of the enclosing moof box for the first track fragment, or to the end of the previous track fragment's data for subsequent fragments.

Calculation with Track Run (trun) Offsets

Once the tfhd establishes the base data offset, the actual position of individual samples is resolved in conjunction with the Track Run box (trun):

  • If the trun box contains a data-offset field (indicated by the data-offset-present flag 0x000001), that value is added directly to the base_data_offset from tfhd.
  • The resulting value points directly to the first byte of the first sample in the corresponding mdat box, with subsequent sample locations calculated sequentially based on individual sample sizes.

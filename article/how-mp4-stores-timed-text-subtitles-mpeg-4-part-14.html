How MP4 Stores Timed Text Subtitles (MPEG-4 Part 14)

MPEG-4 Part 14 (the standard MP4 file format) defines the storage of timed text subtitles by embedding them as dedicated elementary streams within the ISO Base Media File Format (ISOBMFF) container architecture. Utilizing the MPEG-4 Part 17 (3GPP Timed Text) standard, subtitles are structured into discrete data samples paired with metadata tracks. This format allows subtitle text, font styles, colors, positioning, and timing coordinates to be stored synchronously alongside audio and video tracks inside a unified media container.

Track Structure and Identification

MPEG-4 Part 14 organizes all media as distinct tracks (trak boxes) located within the movie box (moov). Timed text tracks follow the same hierarchical box model as video and audio streams:

  • Handler Reference (hdlr): Defines the track type using the four-character code (FourCC) sbtl (subtitle) or text (timed text), informing the demuxer that the track contains text data.
  • Media Information (minf): Contains the text media information header (gmhd or nmhd), which declares general rendering parameters.
  • Sample Table (stbl): Indexes the location, duration, and specific decoding properties of each subtitle sample.

Sample Description Box (stsd) and tx3g Format

The sample description box (stsd) inside the sample table identifies the coding format using the FourCC tx3g. The tx3g sample entry acts as the global configuration for the subtitle track and contains:

  • Display Flags: Bitmasks controlling default rendering behavior, such as vertical text display, continuous scrolling, or whether background filling is enabled.
  • Default Text Box: Coordinate specifications defining the default bounding box (top, left, bottom, right) within the video track's coordinate plane.
  • Default Style Record: Fallback styling rules, including standard font ID, font size, text face attributes (bold, italic, underline), and default RGBA color values for text and background.
  • Font Table Box (ftab): A mapping list assigning unique font IDs used in the track to specific font family names.

Subtitle Samples in the Media Data Box (mdat)

The actual subtitle contents are stored in the media data box (mdat) as sequential, self-contained samples. Each sample corresponds to a specific duration on the playback timeline and is composed of:

  1. Text Length: A 16-bit integer defining the byte count of the following text payload.
  2. Text String: The raw subtitle text, encoded exclusively in UTF-8 or UTF-16 format.
  3. Modifier Boxes (Optional): Appended immediately after the text to override global styles for specific character ranges or entire frames:
    • Style Box (styl): Applies styling (color, size, weight) to designated character index ranges.
    • Highlight Box (hlit): Highlights specific character ranges for effects such as karaoke.
    • Highlight Color Box (hclr): Defines the color used by the highlight box.
    • Position Box (pos ): Overrides the default display box coordinates for the current sample.
    • Hyper Text Box (href): Embeds clickable links associated with designated text ranges.

Synchronization and Timing

Timing in MPEG-4 Part 14 timed text is not written as absolute timestamps within the subtitle text itself (unlike formats like SRT or WebVTT). Instead, synchronization relies on standard ISOBMFF time-to-sample tables:

  • Time-to-Sample (stts): Defines the exact duration (delta) each subtitle sample remains on screen relative to the track's media timescale.
  • Composition Time (ctts): Optional offset mappings if the subtitle composition time differs from the decoding time.
  • Sample Size (stsz) & Chunk Offset (stco/co64): Provide the exact byte offsets and sizes required by media players to seek, demux, and render text frames in real time alongside corresponding video frames.

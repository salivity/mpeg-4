Reference Picture List Reordering in MPEG-4 AVC

This article provides an overview of how MPEG-4 AVC (H.264) manages reference picture list reordering (RPLR) to support complex B-frame configurations. By allowing custom modifications to the default reference picture lists (List 0 and List 1), MPEG-4 AVC enables encoders to assign the lowest reference indices to the most statistically correlated frames. This mechanism minimizes bitstream overhead, supports flexible GOP (Group of Pictures) designs such as hierarchical B-frames, and ensures robust decoding across arbitrary prediction structures.

Default Reference Picture List Construction

In MPEG-4 AVC, B-slices use two reference picture lists: List 0 (L0) and List 1 (L1). When a slice header is decoded, the decoder initializes these lists from the Decoded Picture Buffer (DPB) based on predefined rules:

  1. Short-term Pictures in List 0: Ordered first by descending Picture Order Count (POC) for pictures displayed before the current frame, followed by ascending POC for pictures displayed after the current frame.
  2. Short-term Pictures in List 1: Ordered first by ascending POC for pictures displayed after the current frame, followed by descending POC for pictures displayed before the current frame.
  3. Long-term Pictures: Appended to the end of both lists in ascending order of their LongTermPicNum values.

While this default sorting works well for simple alternating temporal structures, it is inefficient for non-sequential, complex prediction structures.

The Role of RPLR in Complex B-Frame Structures

Complex structures—such as hierarchical B-frame pyramids—often break conventional forward/backward temporal prediction. In a hierarchical structure, a B-frame might use another B-frame far away in display order as its primary reference.

Because entropy coding schemes (CAVLC and CABAC) assign shorter codewords to lower reference indices (e.g., index 0 uses fewer bits than index 3), default list construction can lead to coding inefficiency. If the most frequently used reference frame ends up at index 2 or 3 by default, signaling that reference for multiple macroblocks wastes bit budget.

Reference Picture List Reordering solves this by transmitting explicit reordering instructions inside the slice header, remapping optimal reference frames to index 0 and index 1.

The RPLR Syntax and Execution Mechanism

The slice header contains the ref_pic_list_reordering() syntax structure, which issues a sequence of commands via the syntax element reordering_of_pic_nums_idc. The reordering operates as an iterative displacement process:

  • reordering_of_pic_nums_idc = 0: Subtracts an offset from the current reference picture number (PicNum) to identify a short-term picture and places it at the current target index.
  • reordering_of_pic_nums_idc = 1: Adds an offset to the current PicNum to identify a short-term picture and places it at the current target index.
  • reordering_of_pic_nums_idc = 2: Specifies a LongTermPicNum to place a long-term picture at the current target index.
  • reordering_of_pic_nums_idc = 3: Terminates the reordering loop for the active list.

When a picture is placed at a specific index, all other pictures in the list shift down to subsequent positions, and duplicate entries are removed to maintain list integrity.

Impact on Advanced Inter-Prediction

Managing list reordering directly enhances multiple inter-prediction tools within MPEG-4 AVC:

  • Bi-Predictive Weighting: When using weighted prediction, reordered lists allow precise mapping of linear combinations to specific list pairs.
  • Direct Mode Prediction: Temporal Direct Mode derives motion vectors using the collocated block in the first picture of List 1 (List 1[0]). Custom reordering guarantees that the desired temporal anchor serves as the basis for motion vector scaling.
  • Non-Reference B-Frames vs. Reference B-Frames: Encoders can treat certain B-frames as key references while keeping others as disposable leaves in the prediction tree, structuring lists strictly by correlation rather than temporal proximity.

Picture Order Count POC in MPEG-4 AVC Explained

Picture Order Count (POC) is a fundamental syntax element in MPEG-4 AVC (H.264) video coding that specifies the precise output and display order of decoded frames. Because modern compression schemes frequently decode frames out of temporal sequence to optimize predictive coding efficiency, POC acts as the definitive temporal reference to ensure frames are presented correctly to the viewer. This article explains how POC decouples decoding order from display order, how it is derived across different modes, and its crucial functions in motion vector scaling and buffer management.

Decoupling Decoding Order from Display Order

In advanced video compression like MPEG-4 AVC, video frames are not always decoded in the order they are meant to be viewed. The inclusion of B-slices (bi-predictive pictures) allows a frame to reference both past and future pictures. Consequently, a "future" reference picture must be decoded before any intermediate B-frame that depends on it.

While the syntax element frame_num tracks the sequence in which reference frames are decoded, it cannot indicate when those frames should be displayed. POC resolves this issue by assigning a relative temporal timestamp to each decoded picture, ensuring the Decoded Picture Buffer (DPB) outputs frames in the correct chronological sequence regardless of the order in which they were transmitted and decoded.

The Role of POC in the Decoded Picture Buffer

The Decoded Picture Buffer (DPB) holds decoded pictures until they are either used as references for subsequent frames or output to the display. The DPB uses POC values to execute the "bumping process"—a mechanism that selects the picture with the lowest POC value that is marked as "needed for output" and sends it to the display pipeline.

POC values reset at every Instantaneous Decoder Refresh (IDR) frame, establishing a new temporal baseline for all subsequent pictures. For non-IDR frames, POC values monotonically increase according to the timeline of the source video, handling arbitrary frame reordering seamlessly.

Motion Vector Scaling in Temporal Direct Prediction

Beyond determining presentation order, POC plays an active role in the decoding process itself through motion vector derivation. In B-slice direct mode (specifically temporal direct mode), motion vectors are calculated based on the temporal distance between the current picture and its reference pictures.

The decoder uses the difference between POC values (\(\Delta\text{POC}\)) to determine the exact temporal spacing between frames. By calculating ratios of these POC differences, the decoder mathematically scales motion vectors from co-located blocks to predict movement accurately without requiring extra motion vector data in the bitstream.

Handling Interlaced Video and Field Coding

MPEG-4 AVC supports both progressive and interlaced video content. Interlaced video consists of alternating top and bottom fields that are sampled at distinct points in time.

POC is assigned separately to each individual field as well as to full frames:

  • Top Field POC: Represents the display instant of the top field.
  • Bottom Field POC: Represents the display instant of the bottom field.

This separate tracking allows the decoder to display interlaced fields sequentially with correct temporal parity, avoiding field-inversion artifacts.

POC Derivation Types

MPEG-4 AVC provides three distinct methods for calculating POC, signaled in the Sequence Parameter Set (SPS) to balance bitstream overhead and flexibility:

  1. Type 0: Explicitly signals the least significant bits of the POC in each slice header. This is the most flexible mode and is commonly used when complex frame reordering occurs.
  2. Type 1: Encodes expected POC increments and cycles in the SPS, minimizing the bits needed in individual slice headers for content with predictable frame structures.
  3. Type 2: Derives POC directly from frame_num using mathematical rules, requiring zero additional bits in the slice header. This mode does not support arbitrary reordering or consecutive non-reference frames where display order differs from decode order.

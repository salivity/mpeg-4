MPEG-4 Stereoscopic 3D Stream Data Structures

This article provides an overview of the specific data structures (atoms or boxes) within the ISO Base Media File Format (ISOBMFF) and MPEG-4 container specification (ISO/IEC 14496-12 and ISO/IEC 14496-15) used to signal, link, and synchronize stereoscopic 3D video streams. It details the role of track references, sample entries, and stereo composition metadata required for hardware and software decoders to assemble stereoscopic views correctly.

The Track Reference Box (tref)

In multi-track stereoscopic setups where the left and right eyes are encoded as separate elementary streams, the Track Reference Box (tref) establishes the primary relationship between these tracks. Placed within the Track Box (trak), the tref atom contains specific four-character code (FourCC) reference types:

  • sbas (Stereo Base): Links a dependent eye track (typically the right eye or secondary view) to the base video track (the primary or left eye).
  • vdep (View Dependency): Used in Multiview Video Coding (MVC) configurations to indicate that the decoding of the current track depends on the reference track.

The Stereo Video Box (stvi)

The Stereo Video Box (stvi) is placed inside the visual Sample Entry (such as avc1 or mp4v inside the stsd Sample Table) to declare stereoscopic metadata. It identifies whether the video is stereoscopic and how the left and right views are packed. Key fields include:

  • single_view_allowed: A 2-bit field indicating whether the track can fall back to 2D rendering when 3D display is unsupported.
  • stereo_scheme: A 32-bit identifier signaling the standardization scheme used (e.g., ISO/IEC 14496-12 standard schemes or third-party formats).
  • stereo_indication_type: Defines the spatial arrangement, including frame-packed layouts (side-by-side, top-and-bottom, row/column interleaved) or distinct multi-track combinations, as well as assigning which visual field maps to the left or right eye.

Multiview Video Coding Structures (vwdi and mvcg)

For stereoscopic content encoded via H.264 MVC or HEVC extensions defined in ISO/IEC 14496-15, advanced multiview associations are mapped using specialized sample entries and metadata boxes:

  • mvc1 / mvc2 Sample Entries: Replaces standard 2D sample entries to signal that elementary stream NAL units contain multiview extensions.
  • View Identifier Box (vwdi): Contains the view identification map, directly assigning stream layers to specific eye positions via view_id attributes and defining temporal/inter-view dependencies.
  • Multiview Group Box (mvcg): Aggregates multiple tracks or operational points, grouping tier and view combinations for predictable buffer management and synchronized stereo playback.

Function of the iloc Box in MPEG-4 Files

The Item Location Box, identified by the four-character code 'iloc', is a core structural element in the ISO Base Media File Format (ISOBMFF / MPEG-4 Part 12) responsible for indexing and locating non-timed embedded resources within a file. This article explains how the 'iloc' box works, its internal structure, and how media parsers use it to locate auxiliary data such as HEIF/AVIF image items, metadata, fonts, and external references directly within an MPEG-4 container.

Purpose of the 'iloc' Box

While standard MPEG-4 tracks (video and audio) use sample tables (stbl) to track timed media samples, non-timed data and standalone items rely on the Metadata Box (meta). Inside the meta box, the 'iloc' box acts as a centralized directory. It maps unique item identifiers (item_ID) to their exact physical locations in the file, allowing decoders to retrieve specific resources without scanning the entire bitstream.

How 'iloc' Locates Embedded Data

The 'iloc' box determines resource locations through the following mechanisms:

  • Item Identification: Every embedded resource is assigned an item_ID. The 'iloc' box pairs each item_ID with its byte positions.
  • Base Offsets and Extents: To optimize storage and handle fragmentation, the box defines a base_offset for an item and divides the item's payload into one or more "extents." Each extent contains an extent_offset and an extent_length. The total resource data is reconstructed by concatenating these extents in order.
  • Construction Methods: In newer versions of the specification, the 'iloc' box supports different construction methods (construction_method field). The data can reside directly at an absolute file offset, relative to an Item Data box ('idat'), or relative to another item.
  • Data References: The box includes a data_reference_index pointing to the Data Reference Box ('dref'). This allows the 'iloc' box to point either to internal file locations (index value 0) or to external resources such as distinct local files or URLs.

Internal Fields and Structure

The 'iloc' box optimizes space by using variable-length sizing fields at the header level:

  1. Size Indicators: Fields defining the byte-length of offsets and lengths (e.g., offset_size, length_size, base_offset_size, and index_size). These allow 32-bit or 64-bit precision depending on file size requirements.
  2. Item Count: Declares the total number of indexed resources.
  3. Item Array: A loop containing the location attributes for each item:
    • item_ID: The unique ID of the target resource.
    • data_reference_index: Reference to the resource container inside the 'dref' box.
    • base_offset: The starting reference offset for the item.
    • extent_count: The number of discrete data fragments comprising the item.
    • extent_offset and extent_length: The relative position and size of each fragment.

Significance in Modern Formats

The 'iloc' box is essential for image formats derived from ISOBMFF, such as HEIF (High Efficiency Image File Format) and AVIF (AV1 Image File Format). In these formats, primary images, thumbnails, EXIF data, and alpha masks are stored as non-timed items. The 'iloc' box allows parsers to jump directly to specific image layers or metadata structures instantly, facilitating high-performance decoding and random access.

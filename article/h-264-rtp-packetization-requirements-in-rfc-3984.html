H.264 RTP Packetization Requirements in RFC 3984

RFC 3984 defines the payload format for encapsulating MPEG-4 Advanced Video Coding (AVC), commonly known as H.264, into the Real-time Transport Protocol (RTP). This specification dictates how Network Abstraction Layer (NAL) units are structured, fragmented, and aggregated within RTP packets to ensure efficient delivery over IP networks. By establishing three distinct packetization modes and specific packet structures, the standard allows senders to adapt video transport to varying network Maximum Transmission Unit (MTU) limits, latency requirements, and receiver capabilities.

Network Abstraction Layer (NAL) Encapsulation

MPEG-4 AVC structures video data into NAL units, which consist of a one-byte header followed by the payload (containing video coding layer data or parameter sets). RFC 3984 maps these NAL units directly into the RTP payload.

The standard mandates specific handling of standard RTP header fields:

  • Payload Type (PT): Dynamically allocated to identify the MPEG-4 AVC stream.
  • Timestamp: Represents the sampling instant of the video frame. All NAL units belonging to the same access unit (frame) must carry the exact same RTP timestamp.
  • Marker Bit (M): Set to 1 on the final RTP packet of an access unit to assist the receiver in identifying frame boundaries without parsing internal NAL structures. Set to 0 for all other packets.
  • Sequence Number: Increments by one for each RTP packet sent, enabling packet loss detection and packet reordering.

The Three Packetization Modes

RFC 3984 defines three operational modes signaled during session setup via the Session Description Protocol (SDP) using the packetization-mode parameter:

  1. Single NAL Unit Mode (packetization-mode=0):

    • Designed for legacy applications and low-overhead systems.
    • Only one single NAL unit is permitted per RTP packet.
    • Aggregation packets and fragmentation units are strictly forbidden.
    • The RTP payload header is identical to the NAL unit header.

  2. Non-Interleaved Mode (packetization-mode=1):

    • The most common mode for general IP streaming.
    • Packets must be transmitted in sequential NAL unit decoding order.
    • Supports Single NAL Unit Packets, Single-Time Aggregation Packets (STAP-A), and Fragmentation Units (FU-A).
    • Interleaved packets (STAP-B, MTAP, FU-B) are prohibited.

  3. Interleaved Mode (packetization-mode=2):

    • Designed for networks prone to burst packet loss.
    • Allows out-of-order packet transmission to facilitate interleaving.
    • Supports all packet types, including STAP-B, MTAP16, MTAP24, and FU-B.
    • Requires the inclusion of a Decoding Order Number (DON) in packet payloads to reconstruct the correct decoding sequence at the receiver.

Packet Types Defined in RFC 3984

RFC 3984 specifies three primary categories of RTP payload structures based on the NAL unit type field in the payload header:

1. Single NAL Unit Packets

Used when a single NAL unit fits comfortably within the network MTU. The RTP payload consists solely of the standard H.264 NAL unit (1-byte header + NAL payload).

2. Aggregation Packets

Used to group multiple small NAL units (such as Sequence Parameter Sets, Picture Parameter Sets, or small slices) into a single RTP packet to reduce transport header overhead.

  • STAP-A (Single-Time Aggregation Packet Type A): Combines NAL units that share the same timestamp. Contains 16-bit size fields preceding each aggregated NAL unit.
  • STAP-B: Similar to STAP-A, but includes a 16-bit DON field for interleaved transport.
  • MTAP16 / MTAP24 (Multi-Time Aggregation Packets): Encapsulates NAL units from different access units with distinct timestamps. Includes timestamp offset values (16-bit or 24-bit) for each aggregated NAL unit.

3. Fragmentation Units (FUs)

Used to split a NAL unit that exceeds the path MTU across multiple RTP packets, avoiding IP-level fragmentation.

  • FU-A: Used in Non-Interleaved Mode. It consists of an FU indicator byte, an FU header byte containing Start (S) and End (E) bits, and the fragment payload. The receiver uses the S and E bits to reassemble the original NAL unit.
  • FU-B: Used in Interleaved Mode. It includes the same structure as FU-A with an additional 16-bit DON field.

SDP Signaling Requirements

To establish an RFC 3984 stream, the MIME subtype H264 must be used in the SDP media description. Key parameters include:

  • packetization-mode: Specifies mode 0, 1, or 2 (defaults to 0 if omitted).
  • sprop-parameter-sets: Conveys out-of-band Sequence and Picture Parameter Sets (SPS/PPS) in Base64 encoding.
  • profile-level-id: Indicates the baseline, main, or high profile and level constraints of the video stream.

Purpose of CENC Metadata in MPEG-4 Containers

This article provides an overview of the purpose and function of Common Encryption (CENC) metadata within an MPEG-4 (MP4/ISOBMFF) container. It explains how CENC standardizes content protection, facilitates multi-DRM interoperability, and enables media players to efficiently decrypt and playback protected video and audio streams using a single encrypted asset.

Standardizing Content Protection

Common Encryption (ISO/IEC 23001-7) defines a standard framework for encrypting media content using AES-128 algorithms (primarily AES-CTR or AES-CBC modes) within ISO Base Media File Format (ISOBMFF) containers like MPEG-4. Instead of proprietary encryption formats, CENC standardizes where and how encryption metadata is stored inside the file structure.

Enabling Multi-DRM Interoperability

The primary purpose of CENC metadata is to allow a single encrypted media file to be decrypted by multiple Digital Rights Management (DRM) systems, such as Google Widevine, Apple FairPlay, and Microsoft PlayReady.

This is accomplished through specific metadata structures called "boxes" (or atoms) in the MP4 file:

  • pssh (Protection System Specific Header): Contains DRM-specific initialization data (such as key IDs and system IDs). Each DRM client uses its corresponding pssh box to contact its license server and retrieve the decryption key without requiring different versions of the underlying media file.
  • tenc (Track Encryption Box): Defines default encryption parameters for an entire track, including encryption scheme, default Key ID (KID), and default Initialization Vector (IV) size.
  • senc (Sample Encryption Box): Stores per-sample encryption details, including specific IVs and subsample encryption byte-ranges (defining which bytes are encrypted and which remain clear, such as NAL unit headers in video).
  • sinf (Scheme Information Box): Informs the player's demuxer that the track is encrypted and specifies the encryption scheme type (such as cenc or cbcs).

Facilitating Efficient Decryption and Playback

CENC metadata allows the media player to separate container parsing from decryption:

  1. Demuxing: The player reads the MP4 container structure and identifies encrypted tracks via the sinf metadata.
  2. License Acquisition: The player extracts the pssh box for the supported DRM system and passes it to the Content Decryption Module (CDM) to request the decryption key.
  3. Sample Decryption: Using the per-sample data from the senc and tenc boxes (KID, IVs, subsample ranges), the CDM decrypts the payload samples just before decoding.

Cost and Storage Optimization

By embedding standard CENC metadata into the MPEG-4 container, content providers eliminate the need to encode, encrypt, and store distinct files for every target DRM platform. A single MP4 asset can be distributed globally across diverse operating systems and devices, drastically reducing storage costs and Content Delivery Network (CDN) cache fragmentation.

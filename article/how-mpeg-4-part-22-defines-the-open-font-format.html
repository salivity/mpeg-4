How MPEG-4 Part 22 Defines the Open Font Format

This article provides an overview of ISO/IEC 14496-22 (MPEG-4 Part 22), officially designated as the Open Font Format (OFF). It examines how the standard establishes an open, cross-platform specification based on OpenType technology, detailing its underlying table architecture, support for multiple outline formats, advanced typographic layout capabilities, and role within digital multimedia environments.

Origins and Standardization

MPEG-4 Part 22, formally known as ISO/IEC 14496-22, was adopted to establish an international standard for scalable digital fonts. In 2007, Microsoft and Adobe contributed the OpenType specification (version 1.4) to the ISO/IEC Moving Picture Experts Group (MPEG) to make the format an open, royalty-free standard. The resulting specification, the Open Font Format (OFF), maintains functional equivalence with the OpenType specification, ensuring backward and forward compatibility between .otf, .ttf, and .off font files.

The sfnt File Structure

At its core, MPEG-4 Part 22 defines font files using the modular sfnt (spline font) container architecture. An OFF file begins with an offset table that serves as a directory for all other components of the font:

  • Table Directory: Contains records of every table in the file, identifying each by a unique 4-byte tag along with its checksum, byte offset, and length.
  • Required Base Tables: The standard mandates essential tables for basic rendering, including:
    • head: Font-level metadata, version information, and coordinate scaling factors.
    • maxp: Maximum memory and performance profiles (e.g., maximum glyph and point counts).
    • hhea and hmtx: Horizontal header and horizontal metrics data.
    • cmap: Character-to-glyph indexing tables that map character encoding systems (primarily Unicode) to specific glyph IDs.
    • name: Multilingual naming and copyright metadata strings.
    • OS/2: Metrics required for consistent cross-platform display across different operating systems.

Dual Outline Representation

MPEG-4 Part 22 accommodates two distinct outline technologies within the same container model:

  1. TrueType Outlines (glyf and loca tables): Uses quadratic Bézier curves. It includes an instruction set for font hinting, which optimizes glyph legibility at low screen resolutions.
  2. Compact Font Format / PostScript Outlines (CFF or CFF2 tables): Uses cubic Bézier curves. It offers higher data compression and relies on declarative "hints" interpreted by rasterizers rather than procedural bytecode.

By permitting both outline representations, the standard allows developers and type foundries to choose the mathematical representation best suited to their rendering targets and compression needs.

Advanced Typographic Features

To support complex writing systems and professional digital typesetting, MPEG-4 Part 22 defines advanced layout tables:

  • GSUB (Glyph Substitution): Handles context-sensitive glyph replacements, such as typographic ligatures, small caps, fractional forms, and contextual alternates for non-Latin scripts (e.g., Arabic and Indic languages).
  • GPOS (Glyph Positioning): Controls precise glyph adjustments, including kerning, mark-to-base attachments, and mark-to-mark positioning.
  • GDEF (Glyph Definition): Classifies glyphs into categories (e.g., base glyphs, ligatures, marks) and defines attachment points to assist GSUB and GPOS engines.
  • BASE (Baseline Data): Provides alignment points for scripts that use different baselines (e.g., top-aligned Ideographic scripts alongside hanging or Roman baselines).
  • JSTF (Justification): Contains rules and alternates for advanced multilingual text justification.

Integration with MPEG-4 Systems

Beyond standard operating system typography, MPEG-4 Part 22 is explicitly structured to support multimedia frameworks, such as MPEG-4 Part 11 (Binary Format for Scenes, or BIFS) and web environments. It defines mechanisms for:

  • Font Embedding and Streaming: Allowing fonts to be delivered over networks as embedded assets within multimedia streams.
  • Subset Delivery: Transmitting only the required glyph subsets and layout tables necessary for a specific media scene, minimizing bandwidth usage while preserving visual fidelity.

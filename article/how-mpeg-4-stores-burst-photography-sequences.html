How MPEG-4 Stores Burst Photography Sequences

MPEG-4 technology enables the efficient storage of high-density burst photography sequences by combining advanced video-compression algorithms with flexible container architecture. By treating continuous, rapid-fire photo sequences as high-resolution image streams, MPEG-4 eliminates redundant visual data, minimizes storage footprints, and maintains full image fidelity through specialized inter-frame prediction, efficient metadata indexing, and flexible structural tracks.

Inter-Frame Prediction and Temporal Redundancy

Burst photography captures dozens of full-resolution images within fractions of a second, resulting in immense visual overlap between consecutive frames. MPEG-4 leverages temporal redundancy mechanisms to compress these sequences:

  • Intra-Coded Frames (I-Frames): A primary baseline image is stored with full spatial compression, serving as the visual anchor for the sequence.
  • Predicted Frames (P-Frames): Subsequent shots in the burst record only the changes relative to the preceding anchor frame.
  • Bi-directional Predictive Frames (B-Frames): Extremely rapid burst sequences use data from both past and future frames to interpolate motion, drastically reducing file size without sacrificing edge detail or color depth.

Because the camera sensor position and background lighting remain virtually identical across millisecond intervals, inter-frame prediction eliminates up to 90% of repetitive data compared to saving standalone raw or JPEG files.

ISO Base Media File Format (ISOBMFF) Structure

MPEG-4 is built upon the ISO Base Media File Format (ISOBMFF), which provides a box-oriented, hierarchical file structure ideal for managing high-volume image bursts.

  • Sample Tables (stbl): The container maintains precise index tables that define the exact byte offsets, decoding timestamps, and frame sizes for every individual shot in the burst.
  • Track Separation: Visual payload data is stored in the media data box (mdat), while timing, orientation, and focus metadata reside separately in the movie box (moov). This allows applications to index, navigate, and display thumbnails instantly without loading the entire payload into memory.
  • Edit Lists (elst): Edit lists map specific subsets of frames, enabling cameras to non-destructively flag the "best shot" or create looped previews without duplicating image data.

Motion Vector Estimation

High-speed burst sequences often capture fast-moving subjects. MPEG-4 utilizes motion estimation algorithms to track moving pixel blocks across the frame grid. Rather than re-encoding a moving subject in every frame, the encoder calculates motion vectors that describe the displacement of pixel blocks from one frame to the next. The file only stores these directional vectors and the residual error, allowing high-density continuous action to be reconstructed cleanly upon playback.

High-Efficiency Intra-Block Spatial Compression

For burst images that do require independent reconstruction, MPEG-4 uses spatial block-level compression:

  • Variable Block Partitioning: Encoders segment images into dynamic macroblocks (or Coding Tree Units in MPEG-4 Part 10/AVC and HEVC derivatives) ranging from large smooth regions to tiny, detailed blocks around complex textures.
  • Directional Intra-Prediction: Neighboring pixels within the same frame are used to predict adjacent pixel values, compressing static structural elements before temporal compression is applied.

Non-Destructive Frame Extraction

MPEG-4 architecture enables discrete frame extraction directly from the compressed sequence. Applications can parse the sample description and reference tables to extract a single high-resolution still image as a standalone file without needing to decode or rewrite the remaining burst sequence.

How pitm Box Designates Default Image Displays

In MPEG-4-derived file formats such as the ISO Base Media File Format (ISOBMFF) and derived image specifications like HEIF and AVIF, the Primary Item Box (pitm) serves as an explicit pointer that identifies which item in a multi-item container acts as the default or main image. Instead of requiring a parser to load all embedded assets or guess which image to display first, the pitm box contains a single identifier linking directly to the primary visual payload among thumbnails, image bursts, auxiliary maps, or metadata layers.

Context Within ISOBMFF and the Meta Box

Unlike traditional MP4 files that organize continuous audiovisual content into timed "tracks," untimed visual items (such as static images, image sequences, or configuration properties) are stored as discrete "items" inside a root or track-level Metadata Box (meta).

A single container can store dozens of separate items, including:

  • Master full-resolution images
  • Derived images (e.g., identity transforms, rotations, or grid assemblies)
  • Auxiliary images (such as alpha/depth maps)
  • Thumbnail previews

Because the container does not inherently order these items by presentation priority, the parser relies on explicit box definitions inside meta to determine how to process the file.

Internal Structure of the pitm Box

The pitm box is defined as a FullBox, meaning it includes standard 4-byte box header fields along with a 1-byte version and 3-byte flag descriptor:

  • Box Type: 'pitm'
  • Version 0: Uses a 16-bit unsigned integer (item_ID) to reference items with IDs up to 65,535.
  • Version 1: Extends the item_ID field to a 32-bit unsigned integer to support larger item collections.
  • Flags: Set to 0.
  • Payload: The specific item_ID representing the default image.

How Parsers Resolve the Default Image

When an image rendering engine processes an ISOBMFF-derived image file, it follows a structured sequence:

  1. Locate the Meta Box: The parser navigates to the top-level 'meta' box.
  2. Read the Primary Item Box: It extracts the item_ID specified inside the 'pitm' box.
  3. Cross-Reference Item Information (iinf): The parser checks the Item Information Box to determine the format and properties associated with that item_ID (such as codec type, MIME type, or item protection).
  4. Locate Data Extents (iloc): The parser queries the Item Location Box (iloc) using the extracted item_ID to find the exact byte offsets and lengths where the primary image's compressed bitstream is stored inside the Media Data Box (mdat).
  5. Render the Display: The parser decodes and displays the targeted payload immediately, ignoring secondary assets like thumbnails or alpha channels until explicitly requested.

Fallback and Best Practices

If a container contains untimed image items but lacks a pitm box, the file structure becomes ambiguous. Conforming HEIF and AVIF readers will typically fall back to treating the first valid image entry found within the Item Information Box (iinf) as the display image, but standard compliance requires the presence of 'pitm' whenever a single visual representation must be unambiguously presented as the primary cover image.

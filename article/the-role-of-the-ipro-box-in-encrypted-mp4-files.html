The Role of the ipro Box in Encrypted MP4 Files

This article provides an overview of the Item Protection Box (ipro) within the ISO Base Media File Format (ISOBMFF) and MPEG-4 standard. It details how the ipro box functions as a centralized metadata container for Digital Rights Management (DRM), how it indexes protection schemes for static items, and how media parsers use this information to decrypt content securely.

In the ISO Base Media File Format (ISO/IEC 14496-12), the Item Protection Box, identified by the four-character code ipro, is designed to manage the protection mechanisms of individual items within a file. While track-level data like streaming audio and video typically rely on Sample Encryption (senc) or Common Encryption (cenc) structures, the ipro box specifically handles static objects—such as embedded images, metadata items, fonts, or auxiliary files—contained within the Meta Box (meta).

Structure and Components

The ipro box is a container box that houses an array of protection schemes. Its primary components include:

  • Item Protection Count: A numeric field that indicates the total number of protection mechanisms specified within the box.
  • Protection Scheme Info Box (sinf): One or more nested sinf boxes that describe the specific encryption systems applied. Each sinf box contains:
    • Original Format Box (frma): Identifies the original, unencrypted format of the item.
    • Scheme Type Box (schm): Identifies the cryptographic scheme or DRM system being used (e.g., standard AES, proprietary DRM systems).
    • Scheme Information Box (schi): Holds DRM-specific payload data, such as key identifiers, licensing server URLs, and initialization vectors needed by the decryption module.

How It Works with File Items

The ipro box does not directly contain the encrypted data. Instead, it acts as a lookup table referenced by other structures in the container:

  1. Item Definition: The Item Info Box (iinf) lists every item present in the container. When an item is encrypted, its entry includes a 1-based protection_index.
  2. Protection Mapping: The protection_index corresponds directly to the entry number within the ipro box. A value of zero indicates no protection, while an index of 1 or greater points to a specific sinf box inside ipro.
  3. Item Location: The Item Location Box (iloc) identifies the byte offset and length of the encrypted item within the file.

Decryption Workflow

When a compatible media engine encounters an encrypted MP4 item, the process unfolds in the following sequence:

  1. The parser inspects the meta box and locates the iinf box to find an item's protection_index.
  2. Upon reading a non-zero index, it traverses the ipro box to locate the designated sinf structure.
  3. The parser queries the schm and schi boxes within sinf to initialize the appropriate DRM Content Decryption Module (CDM) and obtain cryptographic keys.
  4. Once the keys and parameters are established, the engine retrieves the raw encrypted bytes specified by the iloc box, decrypts the payload, and presents the unencrypted item to the application.

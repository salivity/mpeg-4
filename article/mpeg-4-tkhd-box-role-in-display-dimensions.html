MPEG-4 tkhd Box Role in Display Dimensions

The Track Header box (tkhd) within the MPEG-4 Part 14 (MP4) and ISO Base Media File Format (ISO/IEC 14496-12) establishes the foundational characteristics of an individual media track, including its spatial, temporal, and visual properties. Regarding display dimensions, the tkhd box defines the visual presentation geometry, specifying how the decoded video frames must be scaled, positioned, and oriented on the playback canvas. This article details the structural mechanisms used by the tkhd box to govern display dimensions, separate display geometry from raw encoded resolutions, and handle transformation operations.

Explicit Width and Height Fields

The tkhd box contains dedicated width and height fields that declare the intended display dimensions of the visual track:

  • Data Format: Both values are stored as unsigned 32-bit fixed-point numbers (16.16 format), consisting of a 16-bit integer part and a 16-bit fractional part.
  • Function: These fields define the visual width and height of the track in abstract coordinate units (typically pixels). They represent the target dimensions of the track before applying the transformation matrix.

Separation of Encoded vs. Display Dimensions

A fundamental function of the tkhd box is decoupling the coded pixel resolution (the elementary stream data) from the rendered display aspect ratio (DAR):

  • Encoded Dimensions: The actual pixel grid size (e.g., \(1440 \times 1080\)) is defined at the decoder level within the Sample Description box (stsd) and the underlying codec parameter sets (such as SPS in H.264/AVC or H.265/HEVC).
  • Display Dimensions: The tkhd box specifies the final output size (e.g., \(1920 \times 1080\) for a 16:9 presentation).

This separation allows media players to display anamorphic video with non-square pixels correctly without needing to re-encode the underlying compressed video stream.

The Transformation Matrix

In addition to width and height, the tkhd box includes a 36-byte transformation matrix (a \(3 \times 3\) affine matrix). This matrix interacts directly with the track's dimensions to determine final screen placement:

  • Scaling: Adjusts the track’s visual size dynamically relative to the overall presentation space defined by the Movie Header box (mvhd).
  • Rotation: Applies track-level rotations (commonly 90, 180, or 270 degrees), frequently utilized by mobile devices to correct video orientation without altering the underlying pixel buffer.
  • Translation and Shearing: Positions the track within the unified movie coordinate system, enabling multi-track layouts (such as picture-in-picture).

Playback Rendering Pipeline

During playback, the media engine processes visual dimensions through the following structural workflow:

  1. Decoding: The decoder outputs raw frames according to the coded sample dimensions.
  2. Dimension Mapping: The player references the tkhd width and height to establish the initial track coordinate rectangle.
  3. Matrix Application: The player applies the tkhd transformation matrix to scale, rotate, or translate the rectangle onto the global presentation canvas defined by mvhd.
  4. Final Presentation: The composited result is rendered to the user display at the proper aspect ratio and orientation.

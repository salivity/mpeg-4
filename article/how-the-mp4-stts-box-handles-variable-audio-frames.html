How the MP4 stts Box Handles Variable Audio Frames

The MPEG-4 (ISO Base Media File Format) Time-to-Sample box, identified by the four-character code stts, provides a compact table that maps media samples to their exact decoding time deltas. By utilizing run-length encoded entries containing sample counts and time durations, the stts box allows the container to dynamically allocate different playback durations to individual audio frames, providing full support for audio tracks with variable frame lengths while maintaining precise synchronization.

Structure of the stts Box

The stts atom resides within the Sample Table box (moov -> trak -> mdia -> minf -> stbl -> stts). It defines the decode time for every sample in a media track through a compact lookup structure.

The binary payload of the stts box consists of:

  • Entry Count: A 32-bit integer indicating the total number of table rows.
  • Table Entries: An array of paired values:
    • sample_count: A 32-bit integer specifying the number of consecutive consecutive samples that share the exact same duration.
    • sample_delta: A 32-bit integer defining the duration of each sample in the group, measured in the track’s specific time scale units (defined in the mdhd box).

Mechanism for Supporting Variable Frame Lengths

In fixed-frame audio formats, an stts table often contains a single entry where sample_count equals the total number of frames in the file and sample_delta is a constant value (such as 1024 timescale units for standard AAC).

When dealing with audio streams that feature variable frame sizes or durations—such as codecs with adaptive packet sizes, voice codecs (e.g., AMR), or tracks with dynamic sample rates—the stts box handles variation by defining multiple table entries:

  1. Run-Length Segmentation: Every time the duration of an audio frame changes, a new entry is appended to the table. If a series of 5 frames has a duration of 960 units, followed by a partial frame of 480 units, and then 10 frames of 1024 units, the stts box records three distinct rows:
    • Entry 1: sample_count = 5, sample_delta = 960
    • Entry 2: sample_count = 1, sample_delta = 480
    • Entry 3: sample_count = 10, sample_delta = 1024
  2. Cumulative Decode Timing: Media parsers calculate the Decode Time Stamp (DTS) of any given sample by summing the products of the preceding sample_count and sample_delta pairs: \[\text{DTS}(n) = \sum_{i=1}^{n-1} \text{delta}(i)\] This calculation allows the demuxer to pinpoint the exact start and end time of every frame, regardless of how drastically frame sizes vary across the timeline.

Practical Applications in Audio

  • Codec Priming and Padding Removal: Many modern audio encoders (such as AAC and Opus) introduce encoder delay (priming samples) at the start and padding samples at the end. The stts box can assign shorter durations to the final partial frame so that playback terminates precisely on the final audio sample.
  • Variable Sample Rate Codecs: Codecs that dynamically change temporal resolution based on content complexity (switching between different transform window sizes) rely on stts entries to maintain continuous audio playback without pitch distortion or buffer underruns.
  • Audio-Video Synchronization: Because each audio frame's exact duration is mapped to the master timeline timescale, the player's synchronization engine can align audio packets with video keyframes, preventing drift across long-duration files.

AVC Bitstream Encapsulation in MPEG-4 Part 15

This article outlines the technical rules and structure defined by ISO/IEC 14496-15 for encapsulating Advanced Video Coding (AVC / H.264) bitstreams into MPEG-4 Part 12-based containers (such as .mp4). It covers the transition from Annex B byte streams to length-delimited NAL units, the structure of the AVC Decoder Configuration Record, the differences between sample entry types, and the mechanisms for handling timestamps and random access points.

1. NAL Unit Framing: Length-Prefixing vs. Byte Stream

In standard AVC Annex B byte streams, Network Abstraction Layer Units (NALUs) are delimited by start codes (0x000001 or 0x00000001). Under ISO/IEC 14496-15:

  • No Start Codes: Start code prefixes are stripped from the bitstream.
  • Length Fields: Each NAL unit is preceded by a length field indicating the size of the NAL unit in bytes (excluding the length field itself).
  • Length Field Size: The size of the length field is configured to be 1, 2, or 4 bytes, with 4 bytes (lengthSizeMinusOne = 3) being the industry standard for general compatibility.

2. The AVC Decoder Configuration Record (avcC)

The decoder initialization data is placed in an avcC box located within the sample entry in the sample description box (stsd). The AVCDecoderConfigurationRecord contains critical parameters required to initialize the AVC decoder:

  • Configuration Version: Typically set to 1.
  • Profile, Compatibility, and Level: AVCProfileIndication, profile_compatibility, and AVCLevelIndication bytes.
  • Length Size Minus One: Specifies the byte size of the length field prepending each NALU (e.g., a value of 3 denotes a 4-byte prefix).
  • Parameter Sets: Stored lists of Sequence Parameter Sets (SPS) and Picture Parameter Sets (PPS) NAL units used across the sequence.

3. Sample Entry Types (avc1 vs. avc3)

MPEG-4 Part 15 defines distinct four-character codes (FourCC) for sample entries to denote where parameter sets reside:

  • avc1: Parameter sets (SPS and PPS) are stored strictly out-of-band inside the avcC box. Video samples should not carry redundant SPS/PPS NALUs unless they match the configuration record.
  • avc3: Parameter sets are permitted in-band within the sample stream itself. This mode is widely used in adaptive streaming protocols (such as DASH and HLS with fragmented MP4) where parameter sets may change mid-stream or need frequent repetition for stream switching.
  • avc2 / avc4: Extensions analogous to avc1 and avc3 that allow for parameter sets and slice extensions related to SVC (Scalable Video Coding) or MVC (Multiview Video Coding).

4. Sample and Access Unit Definitions

  • One Access Unit per Sample: An individual MP4 sample corresponds precisely to one AVC access unit (a primary coded picture).
  • Sample Content: A sample consists of all NAL units belonging to that access unit (e.g., Supplemental Enhancement Information (SEI), primary coded slice NAL units, redundant coded slices), each preceded by its designated length field.
  • Prohibited NALUs: End of Sequence (EOS) and End of Stream (EOB) NAL units must not be included within samples unless required for specific multi-sequence splicing architectures.

5. Timing, Reordering, and Random Access

  • Decoding vs. Composition Timing: Because AVC utilizes B-frames (hierarchical and bi-directional prediction), decoding order differs from presentation order.
    • The stts (Time-to-Sample) box provides the Decoding Time (DTS).
    • The ctts (Composition Time-to-Sample) box provides the signed or unsigned offset to calculate Presentation Time (PTS = DTS + Composition Offset).
  • Sync Samples (stss): Random access points corresponding to Instantaneous Decoder Refresh (IDR) frames must be indexed in the stss box.
  • Open GOPs and Recovery Points: Non-IDR random access points (such as Clean Random Access frames or frames relying on SEI recovery point messages) are marked using sample group descriptions (sbgp and sgpd boxes) with a roll or rap grouping type to signal that decoding must begin before the presentation point.

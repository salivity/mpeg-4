How MPEG-4 tref Box Links Elementary Streams

The Track Reference (tref) box in an MPEG-4 (MP4) container establishes explicit logical, functional, and hierarchical relationships between distinct elementary streams. By serving as an internal linking mechanism within individual track headers, the tref box allows demuxers and decoders to recognize when a track requires data from another track—such as scalable video layers, timed metadata, auxiliary visual tracks, or synchronized text—to decode and render the content properly.

Structure and Location of the tref Box

In the ISO Base Media File Format (ISOBMFF) and MPEG-4 specifications, each elementary stream (video, audio, timed text, etc.) resides in its own Track Box (trak). The tref box is an optional container box placed directly inside the trak box alongside the Track Header (tkhd) and Media Box (mdia).

When present, the tref box does not contain raw media data; instead, it contains one or more sub-boxes, each named using a specific Four-Character Code (FourCC). These FourCC sub-boxes define the nature of the dependency, and each contains an array of track_ID integers pointing to the referenced elementary streams.

Defining Dependency Relationships via FourCC Types

The specific relationship between the owner track and the referenced track is dictated by the FourCC of the sub-box inside tref. Common reference types include:

  • dpnd (Dependency): Explicitly marks that the current elementary stream is dependent on the elementary stream identified by the referenced track_ID for decoding.
  • scal (Scalability): Used in scalable codecs (such as SVC or SHVC), linking an enhancement layer track to its corresponding base layer track.
  • cdsc (Content Description): Indicates that the current track contains metadata or descriptive elements (like timed text, audio description, or closed captions) that describe the referenced track.
  • auxl (Auxiliary): Connects auxiliary video data—such as alpha transparency channels or depth maps—to the primary video track.
  • hint (Hint Track Reference): Links a network packetization hint track directly to the source elementary media track it transmits.

The Dependency Resolution Process

When a media parser encounters a track with a tref box, it resolves dependencies through a specific sequence:

  1. Track Registration: The demuxer assigns each elementary stream its designated track_ID from the tkhd box.
  2. Reference Inspection: As each track is initialized, the parser checks for the presence of a tref box to evaluate incoming and outgoing dependencies.
  3. Graph Construction: The parser reads the internal FourCC sub-box to identify the relationship type and extracts the target track_ID values, building an internal dependency graph.
  4. Synchronized Playback/Decoding: The demuxer ensures that prerequisite frames from referenced tracks (e.g., base layers) are decoded prior to processing frames from the dependent track (e.g., enhancement layers) sharing the same presentation timestamp (PTS).

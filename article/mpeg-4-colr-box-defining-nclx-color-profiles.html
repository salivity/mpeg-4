MPEG-4 colr Box: Defining NCLX Color Profiles

The Color Parameter box ('colr') within MPEG-4 and ISO Base Media File Format (ISOBMFF) containers provides essential metadata that instructs decoders and rendering engines how to accurately interpret and display video pixel values. By utilizing the nclx (non-constant luminance) parameter set, the 'colr' box explicitly defines the color primaries, transfer characteristics, matrix coefficients, and dynamic range of the encoded video stream. This standard ensures color fidelity across diverse operating systems, display hardware, and media players without altering the underlying compressed bitstream.

Location and Structure in MPEG-4

The 'colr' box is embedded inside the VisualSampleEntry (within the stsd or Sample Description box) of an MPEG-4 container. When configured for non-constant luminance video, the colour_type parameter within the 'colr' box is defined as the four-character code 'nclx'.

The nclx payload consists of four distinct parameters conforming to ITU-T H.273 / ISO/IEC 23091-2 standards:

  • Colour Primaries (16-bit integer): Specifies the chromaticity coordinates of the red, green, and blue primaries and the reference white point. Common values correspond to standard gamuts such as BT.709 (HD), BT.2020 (UHD/HDR), and DCI-P3 (digital cinema).
  • Transfer Characteristics (16-bit integer): Defines the opto-electronic transfer function (OETF) or gamma curve used to map linear light to digital code values. Common profiles include BT.709 (standard SDR), SMPTE ST 2084 (PQ for HDR10), and ARIB STD-B67 (HLG).
  • Matrix Coefficients (16-bit integer): Specifies the exact mathematical transform matrix required to derive RGB color signals from the YCbCr (or YUV) encoded video samples.
  • Full Range Flag (1-bit / 1-byte field): Dictates the quantization range of the pixel data. A value of 0 indicates standard video/narrow range (e.g., 16–235 for 8-bit luma), while 1 indicates full range (0–255 for 8-bit).

Primary Functions and Practical Significance

  1. Eliminating Color and Gamma Shifts: Without the explicit instructions provided by the nclx payload, media players often guess the color space based on frame resolution. This ambiguity frequently results in crushed blacks, washed-out shadows, or mismatched gamma curves (such as the common QuickTime gamma 1.96 vs. 2.2 shift).
  2. Container-Level Signaling: While codec bitstreams (like H.264 or HEVC) can store VUI (Video Usability Information) parameters internally, many demuxers and hardware decoders rely on the container-level 'colr' box to set up display pipelines before parsing deep bitstream metadata.
  3. Accurate HDR-to-SDR Tone Mapping: In High Dynamic Range (HDR) workflows, the display engine reads the nclx tags to recognize wide color gamuts (BT.2020) and high-peak brightness curves (PQ/HLG), ensuring proper tone mapping on non-HDR displays.

MP4 Edit List Box (elst) Audio-Video Sync Offsets

The Edit List box (elst), located within the Edit box (edts) of an MPEG-4 (ISOBMFF) container, handles initial audio-video synchronization by defining an explicit mapping between the media internal timeline and the presentation timeline. By instructing the media player to apply initial delays, skip pre-roll/priming samples, or start playback at a specific composition timestamp, the elst box ensures that audio and video streams with different starting offsets align perfectly at playback onset.

The Cause of Initial A/V Offsets

Audio and video encoders often produce streams with differing initial timing characteristics:

  • Audio Priming and Delay: Codecs like AAC introduce encoder delay (priming samples) at the beginning of an audio stream, causing valid audio to start slightly after timestamp zero.
  • Video B-Frame Reordering: Video streams using bidirectional prediction (B-frames) require decode timestamps (DTS) to precede composition timestamps (PTS). This composition delay shifts the first displayable frame forward.
  • Asynchronous Capture: Video and audio capture hardware often start recording at slightly different real-world times.

Without container-level instructions, a media player might render the first decoded sample of every track simultaneously, leading to noticeable lip-sync errors.

Structure of the elst Box

The elst box contains an array of edit entries. Each entry consists of three main fields:

  1. segment_duration: The duration of this edit segment in movie timescale units.
  2. media_time: The starting timestamp (in track timescale units) within the media stream to begin playback for this segment. A value of -1 (or 0xFFFFFFFF) denotes an "empty edit."
  3. media_rate_integer & media_rate_fraction: The relative playback speed (typically 1.0 for normal playback).

How elst Resolves Initial Sync Discrepancies

The Edit List manages initial offsets using two primary techniques:

1. Empty Edits (Inserting Initial Delays)

When a track needs to begin after another track has already started playing, the container inserts an empty edit:

  • The media_time is set to -1.
  • The segment_duration is set to the duration of the required delay.

During this interval, the player renders no video (or silence for audio). A subsequent edit entry follows immediately, setting media_time to 0 to begin standard playback, perfectly synchronizing the delayed track with the rest of the presentation.

2. Dwell or Offset Mapping (Skipping Pre-roll and Priming)

When a track contains initial samples that must be decoded for reference but should not be displayed or heard:

  • The media_time is set to the exact timestamp of the first valid presentation sample (e.g., skipping AAC priming samples or initial video decode offsets).
  • The player feeds earlier samples through the decoder to initialize state or references, but discards their output until the stream reaches the specified media_time.
  • The segment_duration matches the active, viewable duration of the track.

Playback Timeline Resolution

By combining empty edits and positive start offsets across individual track edit lists, the MPEG-4 container maps the initial presentation times of both audio and video tracks to a common movie presentation time T = 0. As a result, media engines synchronize playback accurately from the first presented frame without requiring manual track trimming or stream re-encoding.

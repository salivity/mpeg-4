How MPEG-4 Handles Multiple Audio Tracks

The MPEG-4 container format (specifically the MP4 file format, based on the ISO Base Media File Format) manages multiple concurrent audio tracks by encapsulating each distinct language stream as an independent data track within a single file structure. By using hierarchical metadata boxes (or "atoms"), the format assigns language codes, defines playback relationships, and synchronizes each stream to the primary video track, allowing media players to switch seamlessly between languages during playback.

Track-Based Container Architecture

At the core of an MP4 file is a box-based structure. Video, audio, and subtitle streams are stored inside the mdat (Media Data) box, while the structural metadata is housed in the moov (Movie) box.

Inside the moov box:

  • Every audio stream exists as a separate trak (Track) box.
  • If a file contains English, Spanish, and Japanese audio, the container creates three distinct audio trak elements alongside the video trak.
  • Each audio track contains its own codec configurations, sample tables, and bitrates, allowing different tracks to have varying channel layouts (such as 5.1 surround sound for one language and stereo for another).

Language Tagging and Metadata

To help media players identify and display available languages to the user, each audio track contains specific identification metadata within its mdia (Media) and mdhd (Media Header) boxes.

  1. ISO 639-2/T Language Codes: The mdhd box stores a 3-letter language code (such as eng, spa, or jpn) using a packed 16-bit integer format.
  2. Extended Language Tags (elng): For modern implementations requiring regional distinctions (e.g., en-US vs. en-GB), the optional elng box provides complete BCP 47 language tags.
  3. Track Handlers (hdlr): The handler reference box identifies the track component type as soun (Sound), signaling to the demuxer that the data is an audio stream.

The Alternate Group Mechanism

To prevent all audio tracks from playing at the same time, MPEG-4 uses an alternate grouping system defined in the tkhd (Track Header) box via the alternate_group field:

  • Group Assignment: All interchangeable audio tracks are assigned the same non-zero integer in their alternate_group field (for example, alternate_group = 1).
  • Mutual Exclusion: This flag informs the playback software that all tracks in this group are alternatives to each other. The player evaluates the group and enables only one track at a time based on user preference or system default language settings.
  • Secondary Audio: Audio tracks intended for simultaneous playback (such as a director's commentary overlay or an accessibility description track) can be assigned to a different alternate group or flagged with specific user data atoms.

Time Synchronization and Multiplexing

All audio and video tracks reference a common master timeline defined in the mvhd (Movie Header) box.

  • Sample Tables (stbl): Each audio track contains sample-to-time tables (stts) and chunk offset tables (stco or co64). These tables map raw audio packets to precise presentation timestamps (PTS).
  • Interleaving: The actual audio packets for all languages are interleaved (multiplexed) in small chunks inside the mdat box alongside the video frames. This ensures that regardless of which audio language the demuxer selects, the required audio data is read sequentially from the storage drive or network stream without excessive seeking or buffering.

Demuxing and Playback Workflow

When an MP4 file is opened:

  1. The demuxer parses the moov box to discover all available trak elements.
  2. It groups the audio tracks using the alternate_group identifiers.
  3. It extracts the language descriptors from the mdhd/elng boxes to populate the player's audio selection menu.
  4. Once a language is selected, the demuxer extracts and routes only the corresponding audio packets from the mdat box to the audio decoder, while discarding or ignoring the inactive language streams.

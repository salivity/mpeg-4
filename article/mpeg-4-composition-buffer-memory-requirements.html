MPEG-4 Composition Buffer Memory Requirements

The MPEG-4 Composition Buffer (CB) plays a critical role in the MPEG-4 Systems terminal architecture by storing decoded Composition Units (CUs) before they are rendered by the compositor. This article details the specific memory management requirements governing the Composition Buffer, including sizing constraints, memory allocation policies, data persistence rules, and synchronization mechanisms necessary to maintain seamless audiovisual playback without buffer overflow or underflow.

Architecture Overview

In the MPEG-4 terminal model (ISO/IEC 14496-1), elementary streams flow from the network or storage into the Decoding Buffer (DB), pass through the stream decoder, and are output as uncompressed Composition Units directly into the Composition Buffer. The compositor subsequently fetches these units from the CB to assemble the final scene on the display or audio output.

Sizing and Memory Allocation

Memory allocation for the Composition Buffer depends on the specific media type, stream profiles, and level constraints defined in the MPEG-4 specification:

  • Uncompressed Frame Storage: The CB must allocate sufficient contiguous memory to hold raw, uncompressed media samples. For visual streams, this includes YUV/RGB pixel planes along with transparency (alpha) channels for arbitrarily shaped visual objects. For audio streams, it must accommodate raw PCM buffers.
  • Peak Memory Sizing: Buffer capacity must be sized according to the maximum dimensions and bit depth defined in the stream's DecoderConfigDescriptor. It must accommodate peak frame rates and maximum frame sizes to prevent allocation failures during complex scene presentations.
  • Multi-Object Allocation: Because MPEG-4 handles scene composition with multiple independent visual and audio objects, the system must dynamically allocate or partition memory across multiple concurrent composition buffers.

Timing and Unit Lifecycle

The management of data entering and leaving the Composition Buffer relies on strict clock synchronization:

  • Ingress (Decoding Time): A Composition Unit enters the CB immediately after decoding. If a Decoding Time Stamp (DTS) is present, the decoded data is placed into the CB at that precise instant.
  • Egress (Composition Time): A Composition Unit is consumed and rendered at its designated Composition Time Stamp (CTS), synchronized to the Object Clock Reference (OCR) or System Time Clock (STC).
  • Deallocation: Once a CU’s presentation duration expires, its memory must be immediately freed or recycled via a buffer pool to accommodate upcoming decoded frames.

Object Persistence and Retention Rules

Unlike traditional linear video pipelines where frames are discarded immediately after rendering, MPEG-4 supports object-based persistence:

  • Continuous vs. Static Objects: Continuous media (such as video) replaces buffer contents at regular frame intervals. Static media (such as background graphics or 2D sprites) must remain allocated in the CB until an explicit scene update or terminal event instructs the compositor to release the resource.
  • Shared Memory Schemes: To minimize copying overhead, high-performance implementations often utilize zero-copy memory management, where decoded frames in the CB are directly mapped as rendering surfaces for the compositor or GPU.

Overflow and Underflow Prevention

Proper memory management requires the terminal to adhere to the MPEG-4 System Target Decoder (STD) model:

  • Overflow Prevention: The decoder must not output a CU if the target CB lacks adequate space. If the buffer overflows, unrendered data is overwritten, causing visual artifacts or desynchronization.
  • Underflow Prevention: If the compositor queries the CB at a specific CTS and the required CU is absent due to decoding latency, an underflow condition occurs, leading to frame drops or repeated frames.

How MPEG-4 AVC Handles IPCM Macroblocks

In the MPEG-4 AVC (H.264) video coding standard, the Intra Pulse Code Modulation (I_PCM) mode provides a lossless bypass mechanism that transmits raw sample data directly in the bitstream. This article details how the AVC pipeline handles IPCM macroblocks, covering the bypass of traditional transform and entropy coding, bitstream alignment, sample transmission, and subsequent interactions with spatial prediction and in-loop filtering.

Purpose of the IPCM Mode

Traditional AVC encoding relies on intra-prediction, discrete cosine transform (DCT)-based integer transforms, quantization, and entropy coding (CAVLC or CABAC). When an image region contains complex, highly random, or noisy patterns, transform-based predictive coding can actually cause data expansion, requiring more bits than the original uncompressed samples.

The IPCM mode acts as an "escape" mechanism. It guarantees a hard upper limit on the number of bits required to encode a macroblock, preventing buffer overflows and enabling perfect, lossless representation for specific regions when needed.

Bypassing Prediction, Transform, and Entropy Coding

When a macroblock is signaled as I_PCM, MPEG-4 AVC bypasses nearly the entire core compression pipeline:

  • No Spatial Prediction: The encoder does not calculate directional intra-prediction modes (such as 4x4, 8x8, or 16x16 luma prediction).
  • No Transform or Quantization: Residual calculation, forward transform, and quantization steps are entirely skipped.
  • No Entropy Coding: Neither Context-Adaptive Variable-Length Coding (CAVLC) nor Context-Adaptive Binary Arithmetic Coding (CABAC) is applied to the sample payload.

Bitstream Syntax and Byte Alignment

The handling of IPCM data within the bitstream follows a strict sequence:

  1. Mode Signaling: The encoder signals the macroblock type as I_PCM.
  2. Byte Alignment: Because entropy coding operates at the bit level, the bitstream may end on an arbitrary bit position. To handle raw sample data, the encoder inserts zero-valued stuffing bits (pcm_alignment_zero_bit) until the bitstream reaches the next byte boundary.
  3. Raw Sample Transmission: Uncompressed sample values are written directly in raster-scan order.
    • For standard 4:2:0 chroma formats with an 8-bit depth, the encoder writes 256 luma samples (\(16 \times 16\)) followed by 64 \(Cb\) samples (\(8 \times 8\)) and 64 \(Cr\) samples (\(8 \times 8\)), totaling 384 bytes.
    • For higher profiles (e.g., High 10 or High 4:4:4), the bit depth and chroma subsampling adjust accordingly, but samples remain uncompressed.
  4. Resuming Entropy Coding: Once the raw samples are written, the decoder re-initializes its entropy decoding engine (particularly CABAC state engines) to continue decoding subsequent macroblocks.

Interaction with Prediction and In-Loop Deblocking

Even though an IPCM macroblock is transmitted without compression, it fully integrates into the rest of the decoding pipeline:

  • Reference for Adjacent Blocks: The reconstructed raw samples of an IPCM macroblock are stored in the current picture buffer and serve as valid spatial prediction references for adjacent intra-coded macroblocks.
  • Deblocking Filter: The standard AVC in-loop deblocking filter is still applied to the edges of IPCM macroblocks. This prevents visual boundary artifacts between the raw PCM samples and the surrounding transform-coded macroblocks. Boundary strength calculations treat the IPCM block edges according to the standard's defined filtering rules.

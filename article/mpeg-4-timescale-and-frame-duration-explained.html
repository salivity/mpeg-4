MPEG-4 Timescale and Frame Duration Explained

In an MPEG-4 video container and elementary stream, the timescale and frame duration parameters define how time is measured and how long each individual frame is displayed. Together, these two header values govern the video's frame rate (FPS), ensure accurate playback speed, and maintain proper synchronization between video and audio tracks.

Understanding the Timescale Parameter

The timescale (often identified as timescale in MP4 containers or vop_time_increment_resolution in raw MPEG-4 headers) represents the time resolution of the video stream. It defines how many discrete time units, or "ticks," make up one full second.

For example:

  • A timescale of 600 means one second is divided into 600 distinct units.
  • A timescale of 30,000 means one second is divided into 30,000 distinct units.

A higher timescale provides greater precision for sub-second timing, which is necessary for handling non-integer frame rates without cumulative timing drift.

Understanding the Frame Duration Parameter

The frame duration (often represented as fixed_vop_time_increment or the sample delta in the container) specifies the number of time ticks a single frame occupies on the screen before the next frame is presented.

For example, if a video uses a timescale of 600 and each frame lasts for 25 ticks, the frame duration is 25.

Calculating the Frame Rate

The relationship between timescale and frame duration directly determines the video's frame rate using the following formula:

\[\text{Frame Rate (FPS)} = \frac{\text{Timescale}}{\text{Frame Duration}}\]

Using standard broadcast standards as examples:

  • 24 FPS (Film): Timescale = 2400, Frame Duration = 100 (\(2400 / 100 = 24\))
  • 25 FPS (PAL): Timescale = 1000, Frame Duration = 40 (\(1000 / 40 = 25\))
  • 29.97 FPS (NTSC): Timescale = 30000, Frame Duration = 1001 (\(30000 / 1001 \approx 29.97\))

Key Roles in Video Processing

  • Presentation Timing: Decoders rely on these values to create Presentation Time Stamps (PTS), which instruct the display hardware precisely when to render each frame.
  • Audio-Video Synchronization: Media players map both video frame ticks and audio sample rates to a unified playback clock to prevent audio drift.
  • Support for Variable Frame Rates (VFR): In streams where frame duration changes dynamically, the timescale serves as a fixed reference, allowing individual frames to hold distinct duration values without desynchronizing the playback.

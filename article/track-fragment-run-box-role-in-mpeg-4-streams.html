Track Fragment Run Box Role in MPEG-4 Streams

The Track Fragment Run box (trun) serves as a critical indexing component within fragmented MPEG-4 (fMP4) media files, enabling continuous and adaptive streaming protocols like HLS and MPEG-DASH. Located within the Movie Fragment box (moof), the trun box provides detailed, sample-level metadata for individual media chunks. This metadata allows decoders to parse, position, and render video and audio streams seamlessly without requiring an index of the entire file prior to playback.

Fragment-Level Sample Indexing

In standard, non-fragmented MP4 files, global sample tables (stbl) located in the Movie box (moov) index all samples across the entire file. This model fails in live streaming or segmented workflows because the total duration and sample count are not known in advance.

The trun box resolves this limitation by decentralizing the index. It operates within a Track Fragment box (traf) and indexes a contiguous set of samples—known as a run—contained in the subsequent Media Data box (mdat).

Core Functions of the trun Box

The trun box stores several per-sample fields essential for decoding and presentation:

  • Data Offsets: It defines a data_offset that explicitly points to where the payload of the sample run begins inside the mdat container, ensuring the demuxer extracts the exact raw bytes for decoding.
  • Sample Durations: It records the duration of each individual frame or audio block. This allows the playback engine to maintain proper synchronization and timeline continuity between consecutive fragments.
  • Sample Sizes: It lists the exact byte size of every sample in the run, enabling the demuxer to split the raw chunk of data into discrete frames.
  • Sample Flags: It contains decoding flags that indicate whether a frame is a keyframe (sync sample), disposable, or dependent on other frames. This allows players to quickly identify random access points for seeking and stream switching.
  • Composition Time Offsets (CTTS/CTO): For codecs utilizing out-of-order decoding (such as H.264/AVC or H.265/HEVC using B-frames), the trun box provides composition time offsets. This specifies the presentation time relative to the decode time, ensuring frames are displayed in the correct order.

Enabling Continuous and Low-Latency Playback

Because the trun box contains optional defaults inherited from the Track Fragment Header (tfhd), it can operate with minimal overhead by omitting repeated values (such as uniform sample durations or sizes).

By providing localized sample metadata for discrete chunks of data, the trun box allows media engines to continuously append media segments to source buffers. The decoder can immediately process each run of samples as it arrives over the network, making continuous streaming, adaptive bitrate switching, and ultra-low-latency playback technically feasible.

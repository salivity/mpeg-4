Access Unit Delimiter Function in MPEG-4 Streams

The Access Unit Delimiter (AUD) is a specific Network Abstraction Layer (NAL) unit in MPEG-4 Part 10 (H.264/AVC) streams that marks the boundary between individual access units (coded pictures). This article explains the technical function of the AUD in stream parsing, detailing how it simplifies frame detection, signals frame types for trick play and seeking, aids in error recovery, and reduces computational overhead for decoders and streaming parsers.

What Is an Access Unit Delimiter?

In MPEG-4 AVC/H.264 video streams, video data is organized into Network Abstraction Layer (NAL) units. An Access Unit (AU) represents all the data required to decode a single primary coded picture (a frame or field), which may consist of multiple slice NAL units along with associated metadata such as Parameter Sets (SPS, PPS) and Supplemental Enhancement Information (SEI).

The Access Unit Delimiter is designated as NAL unit type 9 (nal_unit_type = 9). When present, it must be the very first NAL unit of an access unit.

Key Functions of AUD in Stream Parsing

1. Frame Boundary Detection

Without an AUD, a parser must inspect the internal syntax of individual slice headers (such as checking if first_mb_in_slice == 0 or observing changes in frame numbers and picture parameter IDs) to determine when the slices belonging to the previous picture have ended and a new picture has begun.

When an AUD is present, the parser simply detects the NAL unit type 9. This immediately signals the start of a new access unit without requiring full parsing of subsequent slice headers, significantly speeding up demuxing and decoding workflows.

2. Signaled Picture Types (primary_pic_type)

The AUD payload contains a concise syntax element called primary_pic_type. This field indicates the types of slices contained within the access unit:

  • I-slices only: Used for keyframes (IDR or non-IDR I-frames).
  • P and I slices: Forward-predicted frames.
  • B, P, and I slices: Bi-directionally predicted frames.

By reading only this byte, media parsers can filter frames without reading or decoding the video payload. This is essential for:

  • Trick-play modes: Implementing fast-forward or rewind by filtering and decoding only I-frames.
  • Thumbnail generation: Quickly finding random-access keyframes.
  • Adaptive streaming: Assisting packagers in identifying segment and GOP boundaries.

3. Stream Splicing and Packetization

In streaming protocols (such as RTP) and container formats (such as MPEG-TS or MP4), parsers must package discrete frames into individual packets or sample entries. The AUD provides an unambiguous separator that simplifies packaging:

  • In MPEG-TS, AUDs often align with the start of a PES (Packetized Elementary Stream) packet, simplifying demuxing.
  • In Byte Stream Formats (Annex B), where start codes (0x000001 or 0x00000001) separate NAL units, the AUD ensures unambiguous frame separation even across fragmented transmissions.

4. Error Recovery and Resynchronization

If data corruption or packet loss occurs in transit, a parser can lose track of where a frame begins and ends. Scanning for an AUD allows the parser to discard malformed data and safely resume parsing at the start of the next complete access unit.

Summary

While the Access Unit Delimiter is optional in the MPEG-4 AVC specification, its inclusion reduces CPU overhead during stream parsing, standardizes picture boundary detection, enables fast picture-type inspection, and enhances stream robustness across transport networks.

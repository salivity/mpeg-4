MPEG-4 sbgp Box: Linking Frames to Sample Groups

The Sample-to-Group box (sbgp) in the ISO Base Media File Format (ISOBMFF / MPEG-4 Part 12) provides an efficient mechanism for assigning individual media samples (video frames or audio packets) to specific characteristics, playback properties, or processing profiles. Instead of attaching redundant metadata to every individual sample, the sbgp box uses run-length encoding to map continuous sequences of samples to specific entries defined inside a paired Sample Group Description box (sgpd). This decoupled architecture allows decoders and media engines to apply customized handling—such as selective encryption, random access recovery, or dynamic layering—to precise subsets of frames.

The Role of sbgp and sgpd

The grouping mechanism relies on two complementary boxes:

  1. Sample Group Description Box (sgpd): Serves as a lookup table storing the actual profile definitions, configuration parameters, or metadata entries.
  2. Sample-to-Group Box (sbgp): Serves as the mapping index that links each frame in the track to an index within the sgpd table.

Both boxes share a matching 4-character identifier called the grouping_type (for example, seig for CENC sample encryption, or roll for gradual decoder refresh). This identifier establishes the specific category of processing to which the mapping applies.

Internal Structure and Mapping Logic

The sbgp box minimizes file size overhead by grouping consecutive samples that share the same configuration into run-length entries. Each entry in the sbgp box contains two primary fields:

  • sample_count: The number of consecutive samples that share the assigned profile.
  • group_description_index: A 1-based index referencing the specific profile in the corresponding sgpd box.

If a sample is assigned a group_description_index of 0, it indicates that the sample does not belong to any group of that type and requires default or standard processing. A value greater than zero directs the demuxer to the n-th entry of the matching sgpd table.

Step-by-Step Processing Flow

When a media player or demuxer parses an MPEG-4 container:

  1. Type Matching: The parser identifies the required processing feature (e.g., selective decryption) and locates the sbgp and sgpd boxes with the corresponding grouping_type.
  2. Sequential Mapping: As the demuxer reads media samples sequentially, it tracks the cumulative sample_count from the sbgp table to determine the current sample's group index.
  3. Profile Lookup: The demuxer fetches the configuration parameters stored at the corresponding index in the sgpd box.
  4. Execution: The decoder or rendering engine applies the retrieved properties (such as key identifiers, subsample mapping, or temporal layer flags) directly to that sample before rendering or decoding.

Practical Applications

  • Common Encryption (CENC): Identifies which frames are encrypted, specifying unique initialization vectors (IVs) and key identifiers per group.
  • Gradual Decoder Refresh (GDR / Roll Groups): Marks non-IDR recovery points, informing the decoder how many frames must be decoded before the video stream is fully synchronized.
  • Temporal and Spatial Sub-layering: Flags samples for trick-mode play, frame dropping, or dynamic resolution scaling in scalable video codecs.

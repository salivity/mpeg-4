MPEG-4 AVC Sliding Window Reference Marking

This article provides an overview of how MPEG-4 AVC (H.264) decoders manage reference frames using the Sliding Window reference picture marking mode. It explores the Decoded Picture Buffer (DPB) mechanics, the automatic First-In, First-Out (FIFO) eviction process, and the specific signaling syntax used to maintain decoder memory constraints during video playback.

The Role of the Decoded Picture Buffer (DPB)

In MPEG-4 AVC video decoding, inter-predicted frames rely on previously decoded pictures stored in the Decoded Picture Buffer (DPB). Because hardware memory is finite, the decoder must actively manage which frames remain available for reference and which can be discarded. The standard provides two methods for reference picture management: Adaptive Memory Control (using explicit MMCO commands) and the default Sliding Window mechanism.

How the Sliding Window Mode Operates

The Sliding Window reference picture marking mode is an automated, First-In, First-Out (FIFO) queue system. It ensures that the number of active reference frames never exceeds the decoder's allocated capacity without requiring explicit frame-by-frame removal instructions from the video bitstream.

  1. Signaling Activation: The sliding window mode is engaged when the slice header flag adaptive_ref_pic_marking_mode_flag is set to 0. This signals to the decoder that reference picture marking should follow standard automated rules rather than custom memory commands.

  2. Frame Classification: When a newly decoded reference picture enters the DPB, it is initially marked as a "used for short-term reference" picture.

  3. Capacity Threshold Evaluation: The decoder evaluates the maximum number of reference frames allowed, determined by the max_num_ref_frames syntax element defined in the active Sequence Parameter Set (SPS).

  4. FIFO Eviction: If adding the newly decoded picture causes the total number of short-term reference frames to exceed the allowed limit (accounting for any long-term reference frames present):

    • The decoder locates the short-term reference picture with the lowest FrameNum (the oldest in decoding order).
    • This oldest frame is automatically re-marked as "unused for reference."
    • Once a frame is marked as unused for reference and has already been output (displayed), its memory slot in the DPB can be overwritten by incoming frames.

Key Operational Characteristics

  • Zero Overhead: Unlike adaptive marking, which requires transmitting specific Memory Management Control Operation (MMCO) commands in slice headers, the sliding window operates implicitly, saving bitstream overhead.
  • Short-Term Focus: The sliding window only manages frames marked as short-term references. Pictures explicitly marked as "used for long-term reference" are shielded from the sliding window and will not be evicted automatically.
  • Deterministic Synchronization: Because the eviction logic is strictly defined by decoding order and fixed buffer limits, both the encoder and decoder maintain identical reference lists without needing continuous synchronization commands.

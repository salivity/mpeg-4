How MP4 Stores and Indexes HE-AAC with SBR

This article explains the technical mechanisms the MPEG-4 Part 14 (MP4) container format uses to encapsulate, signal, and index High Efficiency Advanced Audio Coding (HE-AAC) streams equipped with Spectral Band Replication (SBR). It covers how the ISO Base Media File Format structure stores the audio stream using specific metadata descriptors, how SBR extensions are signaled for backward and forward compatibility, and how standard sample tables manage the indexing and playback timing of the encoded frames.

HE-AAC and SBR Architecture in MPEG-4

High Efficiency AAC (HE-AAC v1) pairs a standard AAC Low Complexity (AAC-LC) core codec with Spectral Band Replication (SBR). The core codec operates at half the target sampling rate (e.g., 22.05 kHz) to encode lower frequencies efficiently, while the SBR tool synthesizes high-frequency content at the full sampling rate (e.g., 44.1 kHz).

Inside an MPEG-4 container, this dual-rate system is treated as a continuous elementary stream of audio access units (frames). The MP4 container is responsible for two primary tasks: declaring the stream configuration so decoders know how to process both the core and the SBR payload, and indexing the individual frames for synchronized playback and seeking.

The Sample Table Hierarchy

MPEG-4 files store audio track metadata inside an object-oriented box (atom) hierarchy located within the moov (Movie) atom. The path to audio indexing is:

moov \(\rightarrow\) trak \(\rightarrow\) mdia \(\rightarrow\) minf \(\rightarrow\) stbl (Sample Table Box)

The stbl container contains the essential structures for describing and locating audio samples:

  • stsd (Sample Description): Stores codec configuration and stream initialization parameters.
  • stts (Time-to-Sample): Maps frame counts to playback duration.
  • stsz / stz2 (Sample Sizes): Defines the byte size of each individual audio access unit.
  • stsc (Sample-to-Chunk): Groups samples into contiguous chunks.
  • stco / co64 (Chunk Offsets): Stores the absolute file offsets where data chunks reside in the mdat (Media Data) box.

Stream Declaration and SBR Signaling (stsd and esds)

The stsd atom contains an mp4a sample entry. Within mp4a, an Elementary Stream Descriptor (esds) box stores the AudioSpecificConfig (ASC). The ASC defines the Audio Object Type (AOT), sampling frequency, and channel configuration.

Because SBR is an extension layered over AAC-LC, MPEG-4 provides three distinct methods to signal SBR data inside the ASC:

1. Explicit Hierarchical Signaling (Backward-Compatible)

The ASC explicitly defines the base AOT as AAC-LC (AOT 2) along with the core sample rate. It then appends extension data identifying the presence of SBR (AOT 5) and the higher, reconstructed output sampling rate.

  • Legacy Decoders: Read only the core configuration (AOT 2) and ignore the extension, outputting base-band audio at the core rate.
  • HE-AAC Decoders: Read both sections and properly initialize the SBR synthesis filterbank.

2. Explicit Direct Signaling (Non-Backward-Compatible)

The ASC directly declares the base AOT as SBR (AOT 5) and specifies the final output sample rate upfront, followed by internal parameters indicating the underlying core codec (AAC-LC). Legacy decoders that do not recognize AOT 5 will fail to initialize the track.

3. Implicit Signaling

The ASC only declares standard AAC-LC (AOT 2) and the core sampling rate, containing no container-level mention of SBR. The SBR data is embedded entirely within the bitstream as extension_payload() elements inside the raw AAC frames. The decoder must parse the audio frames dynamically to detect and activate SBR processing.

Frame Timing and Indexing (stts and stsz)

Each raw HE-AAC access unit contains both the AAC-LC payload and the SBR extension payload. The container indexes these combined units as single samples:

  • Sample Timing (stts): A standard AAC-LC frame represents 1024 PCM audio samples. When SBR is enabled, it doubles the output sample count to 2048 PCM samples per frame at the reconstructed sampling rate. The stts box maps each frame to its time delta. If the track is declared at the full output rate, the delta per sample in stts is set to 2048 time units relative to the track timescale.
  • Sample Boundaries (stsz): The stsz table lists the exact byte size of each access unit. The byte count includes the core AAC spectral data, scale factors, and the SBR control data (such as envelope scalefactors and noise floor parameters).

Random Access and Seeking

For seeking, the container relies on the Sync Sample Box (stss). Because AAC and HE-AAC are typically encoded using self-contained access units without temporal prediction across frame boundaries, every frame can function as a random-access point. In such files, the stss atom is omitted entirely, signaling that all samples are sync samples (key frames). When a seek operation occurs, the demuxer locates the target frame via stts, resolves its byte location using stsc and stco, and passes the access unit to the decoder, which immediately reconstructs both the core frequencies and the upper spectrum via SBR.

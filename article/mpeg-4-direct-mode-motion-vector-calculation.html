MPEG-4 Direct Mode Motion Vector Calculation

This article explains how MPEG-4 calculates motion vectors for bi-directionally predicted blocks using direct mode. Direct mode increases compression efficiency in bidirectional frames (B-VOPs) by deriving forward and backward motion vectors from previously decoded reference frames rather than encoding the vector coordinates directly into the bitstream. Below is a detailed breakdown of the temporal mechanics, mathematical formulas, and block-handling logic used in this process.

The Purpose of Direct Mode

In standard bi-directional prediction (B-VOPs), an encoder transmits two sets of motion vectors: one pointing forward to a past reference frame and one pointing backward to a future reference frame. Direct mode eliminates the bit overhead of transmitting these vectors by mathematically calculating (or deriving) both vectors from the motion vector of the co-located block in the subsequent reference frame.

Identifying the Co-located Block

To compute direct mode motion vectors, the decoder identifies the spatially identical block in the temporally subsequent anchor frame (typically a P-VOP). The decoder reads the motion vector already calculated and stored for that co-located macroblock or sub-block.

If the co-located macroblock uses a single \(16 \times 16\) motion vector, that single vector is used for the entire current macroblock. If the co-located macroblock was coded using \(8 \times 8\) partition mode (four motion vectors), MPEG-4 calculates distinct direct mode vectors for each corresponding \(8 \times 8\) sub-block.

Temporal Distance Calculation

The calculation relies on linear temporal interpolation based on frame display times. MPEG-4 tracks temporal positions using the modulo time base and VOP time increments:

  • \(TR_D\) (Temporal Reference Difference): The temporal distance between the previous reference frame and the subsequent reference frame.
  • \(TR_B\) (Temporal Reference B): The temporal distance between the previous reference frame and the current B-frame.

Scaling Formulas

Assuming the co-located block has a motion vector \(\vec{MV}\), the forward motion vector (\(\vec{MV}_F\)) and backward motion vector (\(\vec{MV}_B\)) for the current block are scaled linearly according to temporal distances:

\[\vec{MV}_F = \frac{TR_B}{TR_D} \times \vec{MV}\]

\[\vec{MV}_B = \frac{TR_B - TR_D}{TR_D} \times \vec{MV} = \vec{MV}_F - \vec{MV}\]

  • \(\vec{MV}_F\) (Forward Vector): Points from the current B-VOP to the past reference frame.
  • \(\vec{MV}_B\) (Backward Vector): Points from the current B-VOP to the future reference frame.

Calculations are performed independently for both horizontal (\(X\)) and vertical (\(Y\)) vector components using integer arithmetic with predefined rounding rules to prevent decoding drift.

Motion Vector Deltas and Special Cases

MPEG-4 allows optional refinement through Direct Mode Motion Vector Deltas (dMVs). When signaled, small correction values are added to the calculated \(\vec{MV}_F\) and \(\vec{MV}_B\) to adjust for non-linear movement without spending the full bit cost of two complete vectors.

If the co-located block in the reference frame is intra-coded (meaning it has no motion vector), the motion vector for the direct-mode block defaults to \((0, 0)\). In this scenario, both the forward and backward vectors point directly to the co-located spatial locations in their respective reference frames.

Understanding the stsd Box in MPEG-4 Decoding

The Sample Description box (stsd) is a fundamental structure within the ISO Base Media File Format (ISOBMFF) and MPEG-4 container specification. Located inside the moov/trak/mdia/minf/stbl hierarchy, the stsd box provides the decoding pipeline with essential metadata, codec configurations, initialization data, and media stream properties. Without the data contained in this box, an MPEG-4 demuxer and decoder cannot identify the compression format, initialize the decoder hardware or software, or properly interpret the raw compressed media samples found in the file.

Codec Identification (FourCC)

The stsd box contains one or more sample entries, each identified by a unique Four-Character Code (FourCC). This code tells the decoding pipeline precisely which decompression algorithm is required:

  • Video Codecs: Identifiers such as avc1 (H.264), hvc1 or hev1 (H.265/HEVC), vp09 (VP9), av01 (AV1), or mp4v (MPEG-4 Part 2 Visual).
  • Audio Codecs: Identifiers such as mp4a (AAC / MPEG-4 Audio), ac-3 (Dolby Digital), ec-3 (Enhanced AC-3), or Opus.

Decoder Configuration Parameters (Extradata)

Nested directly within the specific sample entry inside the stsd box are codec-specific configuration boxes. These payload structures supply out-of-band initialization data (often referred to as "extradata" or "codec private data") required before decoding the first frame:

  • H.264 / AVC (avcC Box): Supplies the Sequence Parameter Sets (SPS) and Picture Parameter Sets (PPS), defining the decoding profile, constraint flags, level, NAL unit length size, and chroma format.
  • H.265 / HEVC (hvcC Box): Supplies Video Parameter Sets (VPS), SPS, PPS, and operating tiers.
  • MPEG-4 Systems (esds Box): Supplies the Elementary Stream Descriptor, containing the DecoderConfigDescriptor and AudioSpecificConfig (sample rate indices, channel configurations, and profile levels for AAC audio).

Visual Presentation and Geometry Parameters

For video tracks, the stsd sample entry explicitly specifies the spatial properties needed to configure render targets and frame buffers:

  • Coded Dimensions: Encoded frame width and height in pixels.
  • Resolution: Horizontal and vertical DPI settings.
  • Pixel Aspect Ratio (pasp Box): Defines non-square pixel ratios for anamorphic video.
  • Color Metadata (colr Box): Specifies color primaries, transfer characteristics (such as HDR/SDR curves), and matrix coefficients to ensure correct YUV-to-RGB conversion.

Audio Stream Properties

For audio tracks, the stsd sample entry defines standard audio hardware output configurations:

  • Channel Count: Number of audio channels (e.g., 1 for mono, 2 for stereo, 6 for 5.1 surround).
  • Sample Rate: Timebase frequency (e.g., 44.1 kHz, 48 kHz).
  • Sample Size: Uncompressed bit depth per channel (e.g., 16-bit, 24-bit).

Encryption and Protection Schemes

If the media stream is encrypted (such as in Common Encryption / CENC workflows), the stsd box replaces standard codec FourCCs with encrypted indicators like encv (encrypted video) or enca (encrypted audio). Within these entries, it provides:

  • Protection Scheme Information (sinf Box): Identifies the encryption scheme type (e.g., cenc, cbcs).
  • Track Encryption (tenc Box): Contains default Key IDs (KID), initialization vector (IV) sizes, and pattern protection settings used to route samples through the decryption pipeline prior to decoding.

Data Reference Index

Each sample entry in the stsd contains a data_reference_index. This integer maps media samples to specific location descriptors in the Data Reference (dref) box, allowing the demuxer to know whether to fetch media data from internal mdat boxes or external file resources.

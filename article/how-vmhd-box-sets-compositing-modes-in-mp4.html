How VMHD Box Sets Compositing Modes in MP4

This article explains how the Video Media Header box (vmhd) defines default compositing modes and rendering behavior in MPEG-4 (MP4) and ISO Base Media File Format (ISOBMFF) containers. It covers the structural hierarchy of the box, the specific role of the graphicsmode and opcolor fields in visual blending, and how compliant media decoders interpret these settings when rendering video tracks.

Location and Role in the MP4 Container

In the ISOBMFF and MPEG-4 file structures, the vmhd box resides inside the Media Information box (minf), within the Media box (mdia) of a visual track (trak). Its primary role is to declare general presentation and rendering information specific to video tracks.

The box hierarchy is: moov → trak → mdia → minf → vmhd

While the container stores encoded bitstreams within media data samples, the vmhd box defines how the decoded visual frames interact with the target display surface or other underlying visual tracks.

Structure of the vmhd Box

The vmhd box is a FullBox, meaning it contains standard version and flags fields followed by its specific configuration parameters:

aligned(8) class VideoMediaHeaderBox extends FullBox(‘vmhd’, version = 0, 1) {
    template int(16) graphicsmode = 0;
    template unsigned int(16)[3] opcolor = {0, 0, 0};
}

The fields function as follows:

  • version: An 8-bit integer specifying the format version (typically set to 0).
  • flags: A 24-bit field. In standard video tracks, the lowest bit is set to 1 (hexadecimal 0x000001).
  • graphicsmode: A 16-bit integer defining the compositing mode applied to the video track.
  • opcolor: A set of three 16-bit unsigned integers representing Red, Green, and Blue color values (ranging from 0 to 65535) used as operands for specific graphical compositing modes.

Compositing Modes Defined by graphicsmode

The graphicsmode field specifies the transfer mode used by the rendering engine to paint the video frame. The default and standard values derive from the QuickTime and ISOBMFF specifications:

  • Copy (0x0000): The default compositing mode. The source video frame replaces the target display area entirely, ignoring any underlying tracks or background graphics.
  • Dither Copy (0x0040): Replaces the target area while applying a dither pattern to adapt to lower color-depth displays.
  • Blend (0x0020): Blends the source video with the background based on a mix ratio or color calculations defined alongside the opcolor.
  • Transparent (0x0024): Treats any pixels in the video track that match the RGB values defined in opcolor as completely transparent, allowing background visual elements to show through (basic chroma keying).
  • Straight Alpha (0x0100): Blends the video frame using the embedded alpha channel without premultiplication.
  • Premul Black Alpha (0x0101) / Premul White Alpha (0x0102): Composites video that includes an alpha channel premultiplied against black or white backgrounds.

The Role of opcolor in Blending

The opcolor array acts as a reference or modifier for operations specified by graphicsmode.

For example, when graphicsmode is set to Transparent (0x0024), the renderer checks each pixel in the decoded frame against the 48-bit RGB value (16 bits per channel) stored in opcolor. Pixels matching the opcolor are omitted from rendering. In modern MPEG-4 files where standard "Copy" mode is used, opcolor is set to {0, 0, 0} and ignored by the renderer.

Modern Implementation and Compatibility

In modern video workflows (such as H.264, H.265, and AV1 video in MP4), complex compositing is generally handled at the application, canvas, or shader level rather than relying on container-level graphics modes. Consequently:

  1. Most standard MP4 encoders write graphicsmode = 0 (Copy mode) and opcolor = {0, 0, 0} by default.
  2. Compliant decoders read the vmhd box to verify that the track is a video track and confirm standard overwrite rendering.
  3. If non-zero legacy transfer modes are encountered, modern media players may either execute the requested compositing mode or fall back to standard 0x0000 (Copy) rendering to prioritize native playback performance.
